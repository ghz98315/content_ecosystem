# 双人播客参考图与背景变体工作流完整方案

> 文档状态：待确认，尚未开发  
> 适用范围：健康类双人播客  
> 创建时间：2026-08-13 17:20:49（Asia/Shanghai）  
> 核心目标：以用户提供的参考图建立稳定的双人播客角色母版，再根据文案主题只修改背景，最终使用 3～4 张高度一致的画面完成整条播客视频。

## 0. 已确认执行决策

本方案分两期执行：

1. 当前测试期继续使用系统已经实现的单张双人主视觉，先完成健康类双人播客从采集、清洗、改写、审核、书籍信息、双音色 TTS 到成片的真实闭环。
2. 单张主视觉闭环验收通过后，再开发参考图背景切换，不阻塞本轮内容、声音和成片测试。

背景切换阶段采用“固定前景合成”作为正式技术路线：

- AI 只负责一次性制作角色母版及生成 2～4 张纯背景。
- 母版确认后，将人物、服装、桌面、话筒和书籍提取为固定透明前景图层。
- 每张成片画面都复用完全相同的固定前景，由程序与不同背景合成。
- 蒙版用于前景提取和边缘保护，不对 3～4 张完整人物画面反复进行局部重绘。
- 单人口播继续使用现有九宫格生图，双人播客背景切换作为独立图片模式开发。

当前单张主视觉测试基线已于 2026-08-13 完成自动回归：Worker 107 项测试通过、Python 编译通过、Web production build 通过；线上播客男声和播客女声均处于启用状态并已配置试听样本。真实任务成片仍为待验证。

## 1. 需求结论

双人播客图片不沿用单人口播的逐分镜九宫格方案，也不是根据每段文案重新生成一套人物。

本方案需要建立一张经过人工确认的“双人播客角色母版”。主持人和嘉宾的位置、人物形象、服装、坐姿、桌面、话筒、书籍及主要前景元素在母版确认后全部锁定。后续根据文案生成 3～4 张画面时，只允许改变人物背后的背景区域。

最终 3～4 张图片表达的是同一场播客在不同内容主题下的背景变化，而不是不同人物、不同演播室或不同拍摄场次。

## 2. 用户提供的输入

创建健康类双人播客任务时，用户提供：

- 一张清晰的双人播客参考图，推荐 JPG、PNG 或 WebP。
- 主持人与嘉宾的身份对应关系。
- 是否交换主持人和嘉宾的左右位置。
- 可选的服装调整要求。
- 可选的桌面物件调整要求。
- 可选的书籍封面图或书籍信息。
- 图片使用权确认。

参考图建议满足：

- 两位人物主体完整、无遮挡。
- 人脸、发型、衣服边缘清晰。
- 桌面、座位和背景边界容易识别。
- 分辨率足够支持竖屏视频中的横向画面区域。
- 不带水印、平台标识和无法授权使用的人物素材。

参考图质量不足时，系统应提示更换图片，不能直接进入正式生图。

## 3. 第一阶段：生成并确认角色母版

### 3.1 母版的作用

角色母版是固定透明前景的唯一视觉源图，负责锁定人物和前景一致性。每张最终画面都必须叠加同一份透明前景，不能用上一张合成图继续生成下一张，避免人物和服装逐代漂移。

### 3.2 母版允许的一次性调整

在母版确认前，允许进行以下调整：

- 主持人与嘉宾左右位置互换。
- 主持人或嘉宾更换服装。
- 调整衣服颜色，但避免复杂标识和文字。
- 更换或增加桌面书籍。
- 调整茶杯、话筒、笔记本等固定物件。
- 统一整体光线、色调和画面风格。
- 适度修正构图和人物比例。

这些修改只能发生在母版制作阶段。母版一旦人工确认，后续背景版本不得再次改变这些元素。

### 3.3 母版锁定内容

必须锁定：

- 两位人物的身份和面部特征。
- 主持人和嘉宾的左右位置。
- 发型、服装、饰品和姿态。
- 人物大小、镜头距离和拍摄角度。
- 桌面位置、形状和材质。
- 话筒、书籍、茶杯等固定物件。
- 人物与桌面的光线方向。
- 整体画面比例和安全区域。

### 3.4 书籍处理建议

书籍本体可以作为母版固定物件，但不建议让图片模型直接绘制真实书名，因为容易出现乱码、错字或封面漂移。

推荐方式：

1. 母版中保留素色无字书籍。
2. 用户上传真实书封或确认书籍信息。
3. 渲染阶段由程序将书封作为稳定图层覆盖到书籍区域。

这样既能保持书籍位置稳定，也能确保书名准确。

## 4. 第二阶段：提取 3～4 个背景主题

### 4.1 提取依据

系统根据最终确认的双人对话稿提取背景主题，主要关注主持人的：

- 开场钩子。
- 核心提问。
- 主题转折。
- 阶段性承接。
- 总结和 CTA 前的收束。

嘉宾回答如果仍属于当前讨论主题，应继续使用当前背景，不应因为说话人改变就立即换图。

### 4.2 数量规则

- 全片最多使用 4 张背景变体。
- 正常目标为 3～4 张。
- 文案只有 2～3 个清晰主题时，允许只生成 2～3 张。
- 不为了凑够 4 张而制造无意义背景。
- 开场与结尾可以复用同一张基础播客背景。

### 4.3 健康类推荐背景方向

背景应保持温暖、明亮、平和，符合中老年观众的审美，同时避免医疗恐吓和高风险画面。

可选方向：

1. 基础书房：用于开场、书籍介绍和结尾。
2. 温暖家庭空间：用于家庭关系、陪伴和情绪主题。
3. 明亮花园或自然窗景：用于生活节奏、舒缓和规律生活主题。
4. 阅读与思考空间：用于书籍观点、认知转变和方法总结。

背景不得出现：

- 医院、病床、手术、药物和医疗器械特写。
- 执法制服、制式帽子和敏感身份标识。
- 阴暗、破败、压抑或惊悚环境。
- 可识别品牌、文字、水印和界面信息。
- 与来源文案无关的健康疗效暗示。

## 5. 第三阶段：固定前景与纯背景合成

### 5.1 为什么不能只用提示词重新生图

仅在提示词中要求“人物保持不变”不能稳定控制结果，仍可能出现：

- 换脸或年龄变化。
- 主持人与嘉宾位置互换。
- 衣服颜色和款式漂移。
- 书籍、话筒或茶杯消失。
- 人物比例、姿势和镜头角度变化。
- 每张图看起来像不同节目。

因此参考图编辑只用于一次性制作角色母版。母版确认后，系统提取固定透明前景，后续只生成不含人物和桌面物件的纯背景，再由程序合成完整画面。

### 5.2 蒙版策略

系统需要将母版分成两类区域：

保护区：

- 两位人物。
- 头发、衣服和饰品。
- 桌面及其边缘。
- 书籍、话筒、茶杯等固定物件。
- 人物和前景投影。

可编辑区：

- 人物背后的墙面、窗景、书架和环境。
- 不影响人物轮廓的远景区域。

蒙版用于从母版提取固定透明前景，并保护人物边缘。背景生成时不再提交完整人物母版进行反复重绘；每张纯背景生成后，由程序叠加同一份前景图层。

### 5.3 光线一致性

虽然人物前景保持像素级不变，但新背景必须遵守母版已有的光线方向、色温和透视关系。背景提示词中应固定：

- 镜头机位不变。
- 人物和桌面完全不变。
- 主光方向不变。
- 景深程度不变。
- 背景亮度不能压过人物。
- 不在背景中新增人物或前景物件。

若背景光线与人物明显冲突，应进入人工复核或重新生成。

## 6. 图片与文案时间轴映射

3～4 张背景图不平均分配全文，而是根据主题边界映射到文案字符范围，再由现有 TTS 时间轴换算为视频时间。

示例：

```json
{
  "visual_mode": "podcast_reference_variants",
  "master_image": "podcast_master.png",
  "master_status": "approved",
  "variants": [
    {
      "index": 0,
      "image": "podcast_background_01.png",
      "theme": "开场与核心反差",
      "char_start": 0,
      "char_end": 420,
      "editable_region": "background_only"
    },
    {
      "index": 1,
      "image": "podcast_background_02.png",
      "theme": "家庭关系与情绪陪伴",
      "char_start": 420,
      "char_end": 980,
      "editable_region": "background_only"
    }
  ]
}
```

切换规则：

- 主题变化时切换背景。
- 主持人提问与嘉宾回答属于同一主题时保持同一背景。
- 画面切换采用柔和叠化，不频繁闪切。
- 每张图片的使用时长不能过短。
- 背景切换点应优先落在对话轮次或语义段落边界。
- 第一张图可作为视频封面基础图。

## 7. 页面工作台设计

### 7.1 新建任务入口

当用户选择“健康类 + 双人对谈”时，增加播客视觉设置：

- 上传播客参考图。
- 主持人位于左侧或右侧。
- 是否交换人物位置。
- 主持人服装要求。
- 嘉宾服装要求。
- 桌面物件要求。
- 上传可选书封。
- 图片使用权确认。

这些设置只影响双人播客，不出现在单人口播任务中。

### 7.2 角色母版确认区

页面并排展示原始参考图和生成母版，并提供：

- 重新生成母版。
- 补充一次性修改说明。
- 确认人物身份与左右位置。
- 确认服装和桌面物件。
- 确认并锁定母版。

锁定后页面明确显示“人物与前景已锁定”。如果用户需要修改人物、服装或书籍，应先撤销确认并重新生成整组背景，不能只修改某一张变体。

### 7.3 背景变体确认区

母版确认后展示 3～4 张背景变体。每张显示：

- 图片预览。
- 背景主题。
- 对应文案范围。
- 实际生成提示词。
- 一致性检查状态。
- 审核通过按钮。
- 只重生成当前背景按钮。
- 人工修改背景说明输入框。

单张背景重生成只替换纯背景，并继续与同一份已确认前景图层合成，不允许重新生成整个人物画面。

## 8. 工作流状态设计

建议双人播客图片阶段包含以下子状态：

```text
等待参考图
  → 母版生成中
  → 等待母版确认
  → 背景主题提取
  → 背景变体生成中
  → 等待背景审核
  → 图片阶段完成
```

控制规则：

- 没有参考图时，双人播客图片阶段不得自动生成通用人物图。
- 母版未确认时，不生成正式背景变体。
- 任一背景变体失败时，只重跑该图片。
- 更改母版后，旧背景变体全部失效并重新生成。
- 修改对话稿导致主题区间变化时，应重新计算映射；背景主题没有变化时可以复用已有图片。
- 图片未审核通过时，不进入最终正式渲染。

## 9. Provider 能力要求

母版制作 Provider 必须支持至少一种受控图像编辑方式：

- 输入参考图并进行图像编辑。
- 输入参考图完成一次性的位置、服装或桌面调整。
- 支持较高的输入图一致性。
- 返回可审计的任务 ID 和生成结果。

背景 Provider 可以继续使用文字生图，但提示词必须只生成纯背景，不得包含人物、桌面或前景物件。如果当前 Provider 不支持参考图编辑，则不能承担母版制作；此时应为双人播客母版单独增加参考图编辑 Provider。单人口播仍保留现有 Provider 和九宫格模式。

Provider 适配前需要验证：

- 是否支持参考图上传或 URL 输入。
- 是否支持透明蒙版或独立蒙版文件。
- 输入、输出尺寸和比例限制。
- 人物肖像与参考图相关的安全政策。
- 单次编辑耗时和费用。
- 失败重试是否会重复计费。
- 是否能保存 Provider task ID 并断点续跑。

## 10. 一致性自动检查

每张合成图生成后，应比较母版与合成图的固定前景区域：

- 人脸区域是否明显变化。
- 发型轮廓是否变化。
- 服装颜色和形状是否变化。
- 人物位置和大小是否变化。
- 桌面边缘是否变化。
- 书籍、话筒和茶杯是否缺失或移动。
- 镜头构图是否发生偏移。

建议采用分层结果：

- `passed`：保护区变化在允许范围内。
- `needs_review`：存在轻微变化，需要人工判断。
- `failed`：人物、服装或固定物件明显变化，阻止使用。

自动检查只能作为质量门，不能替代人工确认人物是否一致。

## 11. 与现有系统的关系

### 11.1 当前已经具备

- 任务可保存 `narration_mode=dual_dialogue`。
- 健康双人改写已有独立提示词和结构检查。
- 双音色 TTS 已按主持人和嘉宾分流。
- 图片索引支持 `char_start`、`char_end`。
- 渲染端可以按字符范围映射到真实 TTS 时间轴。
- 图片审核和单图替换请求已有基础接口。

### 11.2 当前尚未具备

- 双人播客参考图上传入口。
- 角色母版生成和确认门。
- 人物与前景提取蒙版及透明前景图层。
- 参考图编辑 Provider 接口。
- 3～4 个背景主题提取。
- 纯背景生成与固定前景程序合成。
- 保护区一致性自动检查。
- 母版变更后的背景版本失效机制。
- 双人播客专用图片工作台。

### 11.3 当前实现需要替换的部分

当前双人模式只生成一张通用对谈主视觉并贯穿整条视频，且使用纯文本生图。新方案开发后，双人模式应改为 `podcast_reference_variants`；现有单人口播九宫格逻辑保持不变。

## 12. 数据与产物建议

建议新增或保存以下产物：

- `podcast_reference_original`：用户上传的原始参考图。
- `podcast_master_draft`：未确认的角色母版。
- `podcast_master_approved`：已确认母版。
- `podcast_foreground_mask`：人物与前景提取蒙版。
- `podcast_foreground_layer`：已确认的透明固定前景。
- `podcast_background_plan.json`：背景主题和文案区间。
- `podcast_background_variant`：单张背景变体。
- `podcast_images_index.json`：最终图片时间轴索引。
- `podcast_visual_consistency.json`：一致性检查报告。

关键版本字段：

- 参考图版本。
- 母版版本。
- 蒙版版本。
- 对话稿版本。
- 背景计划版本。
- 图片 Provider、模型和任务 ID。
- 生图提示词摘要。
- 人工确认人和确认时间。

## 13. 异常处理和重跑规则

- 参考图上传失败：停留在等待参考图，不启动 Worker 生图。
- 母版生成失败：只重跑母版，不影响上游改写和 TTS。
- 母版审核不通过：允许补充说明后重新生成母版。
- 单张背景生成失败：只重跑该背景变体。
- 人物一致性失败：自动丢弃当前变体并重新编辑。
- Provider 超时：保存任务 ID，重启 Worker 后继续轮询，不重复提交付费任务。
- 用户更换参考图：旧母版、蒙版和全部背景变体标记失效。
- 用户修改人物或服装：创建新母版版本，旧变体不能继续用于新成片。
- 用户只修改背景要求：保留母版，只重生成指定背景。

## 14. 风险与控制措施

| 风险 | 影响 | 控制措施 |
|---|---|---|
| 只靠提示词保持人物一致 | 换脸、换衣、位置漂移 | 所有画面复用同一透明固定前景 |
| 母版 Provider 不支持参考图编辑 | 无法完成一次性人物调整 | 母版使用独立参考图编辑 Provider |
| 参考图人物授权不明确 | 肖像与平台风险 | 上传前要求使用权确认并保留记录 |
| 自动分割人物边缘错误 | 背景污染头发和衣服 | 蒙版预览、边缘扩张和人工确认 |
| 背景光线与人物不一致 | 画面明显拼贴 | 固定光线方向并设置人工复核门 |
| 模型修改桌面书籍 | 书籍错字或消失 | 桌面划入保护区，真实书封程序叠加 |
| 背景切换过密 | 播客观感不稳定 | 最多 4 张，按主题段而非发言句切换 |
| 母版修改后复用旧图 | 版本混用 | 母版版本变化自动失效所有旧变体 |
| 单图重跑重复计费 | 成本不可控 | 持久化 Provider task ID 和幂等键 |

## 15. 开发实施顺序

### P0：Provider 技术验证

- 使用一张实际双人参考图测试一次性母版编辑能力。
- 验证蒙版能否完整提取人物、衣服和桌面前景。
- 生成 3 个纯背景并与同一固定前景合成，比较人物一致性和边缘质量。
- 记录耗时、费用、安全限制和失败行为。

完成标准：确认母版可以稳定编辑、前景可以完整提取、不同纯背景与固定前景可以自然合成。

### P1：参考图上传与母版确认

- 新建任务增加双人播客参考图上传。
- 保存位置、服装、书籍和物件设置。
- 实现母版生成、预览、重生成和人工锁定。
- 保证单人口播创建页面不受影响。

### P2：前景提取与版本管理

- 生成人物和前景提取蒙版及透明前景图层。
- 提供蒙版预览与确认。
- 建立参考图、母版和蒙版版本关系。
- 母版变化时可靠失效旧背景。

### P3：背景主题提取与变体生成

- 从最终对话稿提取最多 4 个主题段。
- 生成人工可读的背景计划。
- 生成不含人物和桌面物件的纯背景，并与同一透明前景图层合成。
- 增加安全提示词和健康类视觉红线。

### P4：背景审核与局部重生成

- 建立双人播客专用图片工作台。
- 展示主题、文案范围、提示词和一致性结果。
- 支持只重生成某一个背景。
- 人物或前景变化时阻止审核通过。

### P5：渲染接入与回归

- 将 3～4 张背景映射到字符和音频时间轴。
- 使用柔和叠化切换背景。
- 验证字幕、说话人、音频和背景主题同步。
- 回归单人口播九宫格、生图审核和成片渲染。

## 16. 验收标准

### 16.1 母版

- 主持人与嘉宾身份和位置正确。
- 服装、书籍和固定物件符合用户确认内容。
- 画面适合竖屏成片中的播客区域。
- 用户可以明确确认并锁定母版。

### 16.2 背景变体

- 最终使用 2～4 张，正常目标为 3～4 张。
- 所有图片来自同一个已确认母版。
- 人物面貌、位置、服装、姿势保持一致。
- 桌面、书籍、话筒和茶杯保持一致。
- 只改变背景，背景与当前文案主题有关。
- 背景不包含危险、医疗恐吓、敏感制服或可见文字。
- 每张图片均经过一致性检查和人工审核。

### 16.3 成片

- 背景在主题变化处切换，不随每句发言频繁闪切。
- 开场、主体和结尾的画面节奏自然。
- 图片时间轴覆盖完整 TTS 音轨。
- 转场没有黑帧、突跳和不连续。
- 字幕、人物和书籍图层不互相遮挡。
- 双人播客新逻辑不影响健康类单人口播九宫格流程。

## 17. 回归测试范围

每个开发阶段完成后自动执行：

- 健康类单人口播改写、生图、TTS 和渲染回归。
- 健康类双人改写结构与合规回归。
- 双音色角色映射和字幕时间轴回归。
- 参考图、母版和背景版本失效回归。
- Provider 任务幂等与 Worker 重启恢复回归。
- 单张背景重生成不修改其他图片的回归。
- 图片索引到渲染时间轴的完整覆盖回归。
- Web production build。

真实任务至少验证：

1. 一条家庭关系主题健康播客。
2. 一条情绪与生活节奏主题健康播客。
3. 一条带书籍 CTA 的健康播客。

## 18. 本轮明确不做

- 不做人物口型同步。
- 不做人物动作视频生成。
- 不根据主持人每一句话切换图片。
- 不生成超过 4 张播客背景图。
- 不允许每张图重新设计人物、服装和桌面。
- 不在背景变体阶段修改主持人和嘉宾位置。
- 不把参考图逻辑接入现有单人口播九宫格。
- 不把真实书名交给图片模型直接绘制。

## 19. 推荐最终工作流

```text
创建健康双人播客任务
  → 上传双人参考图与书封
  → 设置主持人位置、服装和桌面物件
  → 生成角色母版
  → 人工确认并锁定人物与前景
  → 自动生成前景提取蒙版和透明前景图层
  → 从最终对话稿提取 2～4 个背景主题
  → 生成纯背景并叠加同一固定前景
  → 一致性自动检查
  → 人工审核背景变体
  → 按文案和 TTS 时间轴切换背景
  → 渲染并自动回归
  → 人工验收成片
```

## 20. 阶段结论

该需求应作为健康类双人播客图片链路的正式方案。实现重点不是增加图片数量，而是建立“参考图 → 角色母版 → 固定透明前景 → 纯背景生成 → 程序合成 → 时间轴映射”的一致性链路。

开发时必须保持两条图片工作流隔离：

- 健康类单人口播继续使用现有九宫格分镜生图。
- 健康类双人播客使用参考图母版、固定透明前景和 3～4 张背景合成图。

当前代码只具备单张通用双人主视觉，本文档中的参考图上传、母版确认、前景提取、纯背景生成、程序合成和一致性检查均属于待开发内容，需要在单张主视觉真实任务验收后按 P0～P5 实施。
