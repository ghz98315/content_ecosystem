# 开发素材卡

## 2026-08-08 依赖感知重跑与 render 超时收口

- 阶段：开发与回归阶段。
- 用户价值：重跑某一环节时自动使下游产物失效，避免旧成片与新字幕或新音频混用；长时间 render 会明确失败并释放资源。
- 关键变化：新增 `rerun_stage` 原子 RPC；前端保留旧部署回退逻辑；Worker 认领要求任务处于 pending/processing 且全部前置阶段严格 done；render 增加总 deadline 和 ffmpeg 子进程 timeout。
- 验证证据：Worker 单元测试 49 项全部通过；Python 编译、前端 production build、`git diff --check` 均通过。
- 待验证：Supabase 迁移部署后的网页重跑按钮，以及真实任务在 render 超时后的状态收敛；本轮未再次启动长时间成片任务。
- 下一阶段：完成迁移部署和短时 render 冒烟后，再建立 CosyVoice2 独立试听 Provider，不直接替换 Edge TTS 生产链路。

## 2026-08-07 成片视觉收口与下一阶段排序

- 阶段：回归阶段，次阶段为规划。
- 模块：成片渲染、Worker 运行可靠性。
- 用户价值：免责信息保持合规可见，同时降低对主体画面和字幕的视觉干扰。
- 关键变化：免责字号由 5 号视觉层级降为 4 号，浅灰文字按 50% 透明度与背景预混合；本次不重跑线上成片。
- 验证证据：本地 36 项单元测试通过，Python 编译检查通过。
- 边界：免责新样式仅完成本地代码验证，尚未上线成片验收。
- 下一阶段：优先补齐 Worker 常驻守护、在线状态、异常退出拉起和卡死任务恢复，再继续视觉微调。
- 可写角度：视频流水线接近成片后，为什么运行可靠性比继续调几个像素更重要。

## 2026-08-08 Worker 故障注入与恢复

- 阶段：回归阶段。
- 模块：Worker 调度、阶段租约、图片生成断点续跑。
- 用户价值：进程退出或图片供应商超时时，任务不再永久卡在处理中，也不会从头重复消耗生图额度。
- 关键变化：增加阶段心跳、过期 processing 自动回队、Worker 看门狗脚本、图片请求显式超时和按 grid/img 产物断点续跑。
- 验证证据：测试任务前三阶段和改写审核闭环通过；强制结束 Worker 后 image 被自动回收并重新认领；超时明确落为 failed；已有 4 个 grid 和 36 张图未重复生成；39 项本地测试通过。
- 边界：图片供应商连续请求仍发生超时，测试任务尚未完成 book、TTS、render；Windows 开机自启和网页 Worker 在线状态尚未实现。
- 可写角度：可靠的 AI 制造流水线，关键不是永不失败，而是失败后可恢复、可续跑、可审计。

## 2026-08-08 九宫格方案定版与下一阶段规划

- 阶段：验收收口，次阶段为质量平台规划。
- 模块：图片生成、自动质量验收、任务可观测性。
- 用户价值：保留已通过完整成片验证的九宫格方案，在成本可控的前提下优先保障画面清晰度和生产稳定性。
- 关键决策：不引入 16 宫格模式；九宫格继续作为唯一生产规格，本轮不修改图片生成与切割实现。
- 验证证据：真实测试任务以 5 次九宫格请求产出 41 个镜头并完成 1080x1920 成片；本地切割不产生模型费用。
- 下一阶段：优先建立成片自动质检、失败分类、网页状态与重跑控制，再开展页面视觉统一和双人播客流程开发。
- 边界：最终观看体验仍需人工抽检，自动质检用于提前拦截技术性坏片，不能替代内容审美验收。
- 可写角度：AI 视频流水线降本不能只看单次生成价格，还要把清晰度、失败重试和人工返工一起计入。

## 2026-08-08 成片自动质检与生图洁净化

- 阶段：开发与回归阶段。
- 本轮主题：从“流程显示完成”推进到“成片具备可核验的技术质量结论”。
- 关键模块：九宫格生成与切割、成片渲染、任务成片页。
- 解决的问题：九宫格分隔线污染单图、模型生成乱码文字、完成状态无法证明文件可交付。
- 用户可感知变化：新图默认无分隔线和可见文字；切图内缩 2% 清除边缘污染；成片页展示逐项质检结论。
- 关键设计决策：模型负责无字视觉，书名、作者、字幕由程序字体渲染；硬指标失败阻断成片，持续黑帧等审美风险先警告并保留人工复核。
- 验证证据：44 项 Worker 测试通过，前端 production build 通过；真实测试成片 10 项质检全部通过，时长偏差 0.002 秒，无持续 0.5 秒以上黑帧。
- 待验证/边界：无字提示能显著降低乱码但不能数学保证模型永不画出伪文字；最终图片内容和审美仍需抽检。
- 可写标题：AI 视频流水线为什么不能把 `done` 当成交付完成。
- 可直接引用句：自动质检拦截技术性坏片，人工验收负责内容与审美，二者缺一不可。

## 2026-08-08 字幕语义断句规则收口

- 阶段：回归阶段，次阶段为可靠生产规划。
- 本轮主题：把字幕从固定字符截断升级为可验证的中文语义切分。
- 关键模块：字幕分词、TTS 时间轴、成片自动质检。
- 解决的问题：固定词表无法覆盖真实文案，仍会把词语从中间截断或留下两字尾屏。
- 用户可感知变化：字幕按标点、中文词语和复合名词边界切分，每屏不超过 14 字且不显示标点。
- 关键设计决策：采用中文分词、复合名词保护和全局切点平衡；遇到无法容纳的超长词明确失败，不再静默拆词。
- 验证证据：47 项 Worker 测试通过；真实任务整篇文案回放得到 116 屏，最长 14 字、最短 4 字、强制拆词 0 次。
- 待验证/边界：现有线上成片尚未重跑 TTS/render，新规则将在下一次重跑或新任务中生效。
- 下一阶段：先做依赖感知的单环节重跑与渲染超时治理，确保 TTS 重跑后 render 自动失效并能安全恢复，不允许旧成片与新字幕混用。
- 可写标题：字幕不拆词，为什么不能只靠一张固定词表。
- 可直接引用句：字数上限只是约束，真正决定字幕可读性的是语义边界。

## 2026-08-08 TTS 音色切换策略确认

- 阶段：规划阶段。
- 本轮主题：将音色质量作为独立验收门槛，准备评估 CosyVoice2 等克隆音色方案。
- 关键模块：TTS Provider、音频时长与字幕时间轴、成片渲染。
- 用户价值：在不破坏现有稳定链路的前提下，提升配音的辨识度、自然度和视频吸引力。
- 关键决策：暂不直接替换生产 TTS；先完成现有字幕、时间轴、重跑依赖和渲染超时收口，再做独立音色试听与对比。
- 计划验证：同一段文案对比音色相似度、停顿自然度、长句稳定性、音频时长和字幕对齐。
- 待验证/边界：当前代码仅适配 Edge TTS；CosyVoice2/Index-TTS2 需要 Provider 适配、音色参考音频和授权确认。
- 下一阶段：先建立可回退的 TTS Provider 抽象，再接入 CosyVoice2 试听，不直接覆盖现有 Edge TTS 产物。
- 可写标题：为什么高质量音色不能只靠替换一个模型名。
