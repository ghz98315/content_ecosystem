# 网页端商用化优化方案

> 状态：待确认，确认前不修改网页代码。
>
> 本文是网页端优化的唯一有效规划版本，后续同主题旧方案以本文为准。

## 1. 目标与边界

将现有内容创作平台升级为可商用的内容生产工作台，重点提升可读性、操作效率、移动端适配和长期维护能力。

本阶段覆盖：

- 首页任务工作台
- 任务详情与阶段流程
- 改写、书籍确认、图片、TTS、成片页面
- Provider 与音色管理
- 声音复刻上传页面
- 全局视觉、响应式、交互和无障碍

本阶段不改变 worker 的核心业务逻辑、数据库阶段流转和现有成片流程；TTS 的 v3.5 配置继续作为后端能力，网页端仅通过受控设置调用。

## 2. 当前问题基线

- 页面大量使用内联样式，缺少统一的 UI 组件和设计 Token。
- 首页和任务详情主要按桌面端设计，移动端没有完整断点策略。
- 加载、空数据、失败、重试和提交反馈不统一。
- 侧边栏、流程栏、按钮、输入框、表格和状态标签样式不一致。
- 部分页面使用 Emoji 或异常编码字符作为图标和文案。
- 书籍确认、TTS 试听和声音复刻的信息层级不够清晰。
- Provider 和音色目前通过 `.env` 切换，网页端没有安全的配置入口。
- 部分中文文件需要统一为 UTF-8，避免继续产生乱码。

## 3. 视觉系统

### 3.1 产品定位

采用浅色、克制、专业的内容生产工作台风格，优先保证扫描、比较和重复操作效率，不使用营销型 Hero、渐变背景或装饰性卡片堆叠。

### 3.2 设计 Token

统一定义以下 Token，并由所有页面和组件复用：

- 颜色：页面背景、面板背景、主文字、辅助文字、边框、焦点、成功、处理中、等待、失败、需确认。
- 间距：4、8、12、16、24、32、48px。
- 圆角：4、6、8px。
- 阴影：仅用于弹窗、抽屉、浮层和必要的重点操作。
- 字号：12、13、14、16、20、24、28px，建立标题、正文、辅助信息层级。
- 动效：统一时长和缓动，限制在加载、切换、展开和提交反馈。

### 3.3 图标与文案

- 引入 `lucide-react`，替换 Emoji、手工符号和不明确图标。
- 图标按钮提供 tooltip 和 `aria-label`。
- 文案统一 UTF-8，清理乱码。
- 状态文案统一为“待处理、处理中、待确认、已完成、失败、已取消”。

## 4. 页面改造

### 4.1 首页任务工作台

- 顶部标题区、任务统计和主要创建入口。
- 任务列表支持状态筛选、搜索和排序。
- 统一空状态、加载 Skeleton、失败提示和刷新入口。
- 新建任务改为规范表单，明确输入要求、提交状态和错误原因。
- 桌面端使用侧边栏，移动端使用顶部导航和抽屉式任务列表。

### 4.2 任务详情页

- 重做顶部任务信息栏，清晰展示标题、状态、完成进度和主要操作。
- 流程栏改为响应式步骤导航，支持横向滚动和当前阶段强调。
- 取消、删除、重试、确认等操作统一确认弹窗和反馈状态。
- 阶段内容统一放入详情面板，减少页面之间的视觉跳变。

### 4.3 阶段详情

统一重构 ingest、transcribe、clean、rewrite、image、book、tts、render 八个阶段，每个阶段都提供：

- 标题、状态、更新时间和错误信息。
- 核心数据摘要。
- 主操作和次操作。
- 加载 Skeleton。
- 空状态。
- 失败重试。
- 完成后的结果预览。

### 4.4 书籍确认

- 书名、作者、国籍、主题等字段分为可编辑和只读状态。
- 未保存修改有明确提示，确认后显示提交进度。
- 作者和国籍不再限制为只读。
- 表单错误就地显示，避免只在顶部显示模糊错误。

### 4.5 TTS 与音色管理

- Provider 使用分段控制：Edge / CosyVoice。
- 音色使用 profile 选择，不直接暴露 API Key 或内部 endpoint。
- 展示当前模型、音色类型、Voice ID 和可用状态。
- 提供当前音色试听、重新生成和失败重试。
- 保留 Edge 手动兜底入口。
- 切换设置需经过服务端权限校验，并记录当前选择。

### 4.6 声音复刻页面

- 支持拖拽和文件选择上传。
- 校验 MP3、WAV、M4A、文件大小和音频时长。
- 显示上传进度、失败原因和重试按钮。
- 创建 Voice Enrollment 后展示 Voice ID、绑定模型和试听音频。
- 支持多个复刻音色列表、启用状态和删除保护。
- 明确提示音频授权和音频质量要求。

## 5. 响应式策略

统一断点：

- 手机：`< 640px`
- 平板：`640px - 1023px`
- 桌面：`>= 1024px`

具体规则：

- 侧边栏在手机端变为抽屉。
- 流程步骤在手机端横向滚动或折叠。
- 多列内容自动变为单列。
- 表格在手机端转换为字段块。
- 操作控件触控区域不小于 44px。
- 长文本、URL、Voice ID 自动换行。
- 音频播放器和图片预览保持稳定尺寸，不引起布局跳动。
- 检查 375px、768px、1280px 三种基准视口，并覆盖更窄手机宽度。

## 6. 组件重构

建立基础 UI 层：

```text
components/ui/
  Button
  IconButton
  Input
  Select
  Modal
  Drawer
  Badge
  StatusBadge
  Skeleton
  EmptyState
  ErrorState
  Toast
  Progress
  AudioPlayer
  ConfirmDialog
```

建立业务组件层：

```text
components/workspace/
components/task/
components/stage/
components/voice/
```

页面只负责数据获取和业务组合，避免继续复制内联样式和状态逻辑。

## 7. UX 与微交互

- 首次加载使用 Skeleton，不显示突兀的空白或单行“加载中”。
- 提交按钮显示进行中、成功和失败状态。
- 处理中的阶段显示进度或心跳时间。
- Hover、Focus、Pressed 状态统一。
- 弹窗、抽屉和阶段切换使用短过渡动画。
- 失败信息包含原因、影响和可执行的下一步。
- 危险操作必须二次确认。
- 音频播放失败提供重新获取签名 URL 和重试入口。

## 8. 无障碍与规范

- 使用语义化 `header`、`nav`、`main`、`section` 和 `form`。
- 表单控件使用明确的 `label`。
- 图标按钮提供 `aria-label` 和 tooltip。
- 键盘可完成导航、弹窗关闭、表单提交和步骤切换。
- 统一焦点样式和可见焦点环。
- 错误信息使用 `role="alert"`，加载区域使用 `aria-busy`。
- 检查文字与背景对比度，目标达到 WCAG AA。
- 所有动态文本和状态变化不遮挡前后内容。

## 9. 实施顺序

1. 统一 UTF-8 文案、颜色 Token、间距、圆角和字体层级。
2. 建立基础 UI 组件和图标体系。
3. 重构全局布局、侧边栏和导航。
4. 重构首页任务工作台。
5. 重构任务详情和流程导航。
6. 重构八个阶段详情面板。
7. 重构书籍确认和 TTS 试听。
8. 集成 Provider、音色 profile 和 Edge 兜底设置。
9. 完善声音复刻上传和 Voice ID 管理。
10. 完成响应式、无障碍和回归修正。

## 12. 已确认的产品决策

以下决策已确认，后续实施以此为准：

1. 任务列表需要展示已有的内容数据，包括字数、时长、发布时间、点赞、评论和分享；暂不展示粉丝数。
2. 处理方式是正式产品能力，至少包含自动完成和人工介入两种模式。
3. TTS 语速允许按新任务设置，不影响已经开始处理的任务。
4. Provider 和音色设置只对新任务生效，不修改已经进入处理中的任务。
5. 图片数量和图片排布以实际流程产出为准，参考图中的 63 张仅作为布局参考，不作为固定业务上限。
6. 违规图片需要支持单张重新生成，重新生成时必须沿用该镜头对应的原始提示词和上下文。
7. 同一套文案生成多种风格成片属于有价值的当前能力候选，需要先评估 worker 改造范围。
8. 动效预设和知识卡片声明模板属于当前版本范围。
9. 顶部横向流程栏继续作为主要阶段导航，左侧区域作为全局导航、任务列表和公共设置入口，不重复展示阶段流程。
10. 页面需要有舒缓、清晰、有呼吸感的动效，面向宝妈用户时优先降低认知压力，不使用快速闪烁或复杂跳转。

## 13. 详细功能拆解

### 13.1 任务创建与处理方式

任务创建表单增加：

- 来源 URL 或文件输入。
- 处理方式：自动完成、人工介入。
- TTS Provider：Edge、CosyVoice。
- 音色 profile。
- 语速：标准、稍慢、稍快，后续可扩展为数值设置。
- 任务级设置摘要。

这些设置在创建任务时写入任务参数快照。worker 读取任务快照，而不是读取创建之后变化的全局配置，保证任务可复现。

建议数据结构：

```json
{
  "processing_mode": "auto",
  "tts": {
    "provider": "cosyvoice",
    "voice_profile": "cloned_narrator35",
    "model": "cosyvoice-v3.5-flash",
    "speech_rate": 1.0
  }
}
```

### 13.2 顶部流程与左侧公共导航

顶部流程栏保留并强化：

- 当前阶段。
- 已完成阶段数。
- 总进度。
- 预计剩余时间。
- 阶段状态和需确认提示。

左侧不重复放置阶段步骤，改为公共工作台：

- 产品入口。
- 任务列表。
- 新建任务。
- 音色管理。
- 声音复刻。
- 系统设置。
- 当前任务摘要。

桌面端固定左侧栏，平板端可收缩，手机端使用抽屉。这样既保留参考图的阶段效率，又为后续扩展公共功能留下空间。

### 13.3 TTS 配置节点

TTS 设置放在“新建任务”阶段，而不是成片过程中临时修改：

1. 用户创建任务时选择 Provider、音色和语速。
2. 任务创建后，在任务概览中显示配置快照。
3. TTS 阶段显示当前配置，但默认只读。
4. 任务尚未进入 TTS 前，可通过“重新创建任务设置”生成新的任务参数。
5. 已进入 TTS 或之后的任务不允许直接更换音色，避免前后音频混用。

### 13.4 图片生成与违规图片重生成

图片阶段采用“镜头卡片”模型，每张图片记录：

- 镜头编号。
- 对应文案片段。
- 原始提示词。
- 当前图片。
- 审核状态。
- 失败原因。
- 生成批次。

违规图片操作：

1. 用户在单张图片上标记违规或不合适。
2. 页面显示该图片对应的原始提示词和可编辑补充要求。
3. 点击“重新生成本图”。
4. worker 只重跑该镜头，保留原图和新图版本。
5. 用户选择新图后，才替换当前有效图片。

不能直接重跑整个 image 阶段，否则会浪费已生成结果并增加误操作成本。

### 13.5 多风格成片评估

该功能有价值，但当前 render 阶段主要围绕单个固定成片流程组织，不能只做前端按钮。

建议实现方式：

```text
同一文案 / 同一字幕 / 同一音频时间轴
                  ↓
        风格列表 + 每种风格数量
                  ↓
       render job 按风格拆分子任务
                  ↓
      每个子任务独立生成和自动质检
                  ↓
       页面展示多版本成片结果
```

第一版建议支持：

- 一条文案最多选择 2 种风格。
- 每种风格最多生成 1 条成片。
- 共用音频、字幕和图片索引。
- 仅替换布局、动效、色彩和片尾模板。
- 每个风格独立失败、重试和下载。

后续再扩展到同一风格多数量。实现前需要补充 render 参数快照、子任务状态和成片 artifact 关联，预计会同时涉及 worker、数据库和网页。

### 13.6 当前版本的动效与“呼吸感”

面向宝妈用户，动效以降低等待焦虑和明确下一步为目标：

- 页面切换：180~260ms 淡入和轻微位移。
- 阶段切换：当前阶段卡片先出现，内容随后分组进入。
- 处理中：使用低频呼吸动画或进度变化，不使用高频闪烁。
- 生成完成：状态颜色、图标和轻微缩放反馈。
- 错误：局部提示展开，不让页面整体跳动。
- 上传和生成：显示明确的阶段性进度。
- 鼠标悬停：轻微背景变化和边框强调。
- 键盘焦点：清晰焦点环，不依赖颜色 alone。

同时支持 `prefers-reduced-motion`，用户关闭动画时保留状态变化和可读反馈。

## 14. 待技术确认的事项

以下内容已经有产品方向，但实施前需要以现有数据和 worker 能力做一次技术核对：

1. 点赞、评论、分享、发布时间和字数目前分别存在哪些字段，是否需要统一任务统计接口。
2. 自动完成和人工介入是否已经有数据库字段，还是需要新增任务参数。
3. 任务参数快照存放在 `tasks` 还是阶段 `params`，以及前端如何展示。
4. 图片提示词是否已经保存到 artifacts 或 stages，能否支持单图重生成。
5. render 是否能复用同一音频和时间轴生成多风格成片。
6. 动效预设、视频风格和声明模板当前是否已有 worker 参数和模板文件。
7. 新任务设置是否需要保存为个人默认值，还是每次创建任务都重新选择。

这些技术确认完成后，再确定数据库改动和实施批次，避免先做出无法落地的前端控件。
