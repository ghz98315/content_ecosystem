### P1 成片风格与数量确认工作台

### P1.5 语义情绪标注与配音表达

目标：让 TTS 按稿件的语义、叙事位置和内容领域形成可听见但不过度表演的语气层次；不把“增加停顿”误当作情感表达。

首版情绪清单（受控白名单）：

- `plain`：平实叙述。默认回退，不夸张。
- `hook`：反差钩子 / 追问。聚焦、略明亮，用于开头 10 秒和关键反认知句。
- `alert`：警示提醒。沉稳、略压低音高，用于风险、后果、红线与健康提醒。
- `comfort`：释然安抚。稍慢、柔和，用于共情、放下、照顾自己和收束。
- `empathy`：共情低落。克制、不过分悲伤，用于损失、遗憾、困境描述。
- `affirm`：积极肯定。适度明亮，用于希望、改变、可执行建议和正向结果。
- `solemn`：庄重历史。稳定、克制，用于历史人物、史实、纪念和严肃叙述。
- `analytical`：理性分析。清晰、均速，用于经管数据、因果推演和方法论。
- `cta_close`：行动收束。真诚、从容，用于与全文自然衔接的 CTA，不重复煽动。

实施顺序：

1. 在 TTS 前增加独立的“情绪标注”产物：大模型只输出段落范围、白名单标签、置信度和简短理由；不改写原稿。
2. 先对健康类单人口播试运行，再分别为历史社科、经管、双人对谈建立领域映射和角色差异。
3. TTS 读取标注并生成受限 SSML 参数；参数仅允许语速、音高、音量与少量停顿，未知标签、低置信度或接口失败回退 `plain`。
4. 将情绪标注版本、实际生效参数、音频时长写入 artifact；重跑只失效 TTS 与 render，不影响清洗、改写、图片和书籍确认。
5. 增加人工试听面板，至少对钩子、风险段、安抚段、CTA 各抽样一段；同时显示“基线时长 / 情绪版时长 / 增幅”。

验收标准：

- 健康、历史社科、经管、双人对谈各至少 2 条真实任务试听通过，且不影响现有健康类单人口播基线。
- 同稿情绪版相对标准版总时长增幅控制在 5% 以内；不允许通过全篇增加静音制造情绪。
- 标注 JSON 可追溯、可人工覆盖；TTS 与 render 绑定同一标注版本。
- 情绪表达以自然语气差异为准，不承诺演员式“喜怒哀乐”；需要强表演时另行评估原生情感模型或多情绪参考音频。

规划依据：`docs/RENDER_STYLE_QUANTITY_WORKBENCH_WIREFRAME.md`。

- 建立 render profile 与输出版本数据模型。
- 首先实现单风格、单数量、独立版本 artifact，不覆盖历史成片。
- 再扩展每种风格独立数量、多风格共享图片/TTS/字幕、生成前时间与存储预估。
- Worker 模板参数化后才开放真实可提交控件，不展示假选项。
- 第一阶段不同时建设大量模板市场，先验证 2-3 个差异明确的模板。

- “视频号支持”目前指链接识别和人工上传兜底，不代表自动下载已完成。
- 历史社科、经管和双人对谈已有首轮代码，不代表已经通过真实生产验收。
- “成片风格与数量工作台”目前只有规划线框，数据库、Worker 和可提交页面均未实现。
- 图片普通重跑用于断点续跑，会复用旧图；视觉提示词改变后必须使用“按当前风格全量重新生成”。
- 新风格、新领域和矩阵号能力必须保存任务快照，不能修改历史任务的行为。
