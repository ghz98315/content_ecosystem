# 2026-08-10 改写对稿定位节点

## 已完成

- 保留桌面端“合规建议 / 完整改写稿”左右对照布局。
- 每条合规建议增加与正文一致的编号状态：`稿件中已定位` 或 `改写后已移除`。
- 选中的改写稿顶部增加问题定位条，显示风险片段、编号和其在全文中的大致位置。
- 点击左侧建议或定位条，会聚焦正文并选中对应文本。
- 风险词已经被替换时，不再错误提示“找不到”，改为提示用户确认替代表达是否保留原意。
- 移动端定位条自动换行，避免挤压正文编辑区域。
- 根据实际审稿反馈扩大文案显示区域：桌面端编辑区最小高度由 520px 增至 640px，确认稿预览上限由 300px 增至 440px；手机端分别保持为 520px 和 360px，避免操作区被过度推远。

## 用户价值

- 审稿时不需要在上千字文案中手工搜索风险词。
- 可以快速区分“仍需修改”和“模型已经处理，但需要确认语义”的建议。
- 编号在建议区和正文定位区保持一致，适合逐项确认。

## 验证

- `npm.cmd run build`：通过。
- 涉及文件：`web/components/detail/RewriteDetail.tsx`、`web/app/globals.css`。

## 边界

- 原生 `textarea` 不支持在可编辑正文内部持久绘制多段富文本底色；当前方案使用编号定位条和精确文本选区，避免引入不稳定的富文本编辑器。
- 后续如需要正文内永久标注，应单独引入受控的富文本编辑模型并保存纯文本映射，不能直接把 HTML 当成最终配音稿。
