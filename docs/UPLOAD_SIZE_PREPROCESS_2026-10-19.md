# 上传前容量处理（2026-10-19）

## 已实现

- 默认单文件硬上限按50,000,000字节计算；使用96%安全阈值，即48,000,000字节。读取artifacts桶的更小上限并遵守，项目可用STORAGE_FILE_LIMIT_BYTES进一步降低。
- 网页配音、采集兜底、背景音乐、音色样本上传前读取登录保护的容量策略接口。超过对应阈值才加载本地FFmpeg单线程WebAssembly，将音频转MP3；采集视频仅提取用于转写的音轨。原文件不改，云端保存处理后的上传版。
- 背景音乐仍遵守25MiB功能上限；音色样本采用3.5MB请求体安全阈值，避免网页服务请求体限制。
- 本地处理输入最多200MiB；工具加载120秒超时、转码300秒超时；处理后再次检查文件大小与完整时长。无法安全处理时在上传前提示，避免上传半成品。
- 服务端签发上传地址前再次校验。Worker所有文件/字节上传增加前置容量检查，超限媒体在临时副本处理，原件保留；桶限额缓存最多5分钟。
- 成片编码预算随存储阈值收紧；过大文件先压缩再上传。超过6MiB使用分片上传，但分片不能绕过容量限制。
- 本地处理引擎按需加载，运行时文件随网站构建生成并由本站提供；不向额外压缩服务发送用户媒体。运行时来源与GPL授权文本一并发布。

## 验证

- 网页策略与模拟转码20项检查通过。
- Worker容量与真实FFmpeg压缩4项通过：模拟53,760,102字节WAV压至约2.2MB，70秒完整，源文件哈希不变。
- 实际WebAssembly引擎：同一53,760,102字节、70秒模拟音频转MP3得到1,681,493字节，耗时1.886秒（仅转码，不含工具下载）。独立Node引擎验证，不等同于真实浏览器完整上传测试。
- 原有217项Python回归通过，标题26项、工作流13项、播放数据导入22项通过。
- 真实FFmpeg成片缓存集成1项通过。
- Next生产构建通过；真实浏览器完整大文件上传尚未验证。

## 边界

压缩不能保证任意时长/格式都能落入容量上限。输入过大、工具加载失败、文件损坏、无音轨、处理超时、时长变化或仍超限时，明确提示用户导出较小MP3或分段，绝不截断内容。图像仅做保守优化，优化后仍超限会在上传前拦截。不会修改Supabase套餐或扩大存储额度。
