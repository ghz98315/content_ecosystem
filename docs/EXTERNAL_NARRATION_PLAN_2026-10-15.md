# 外部配音驱动国学视频：执行计划

日期：2026-10-15
状态：上传、文稿核对、字幕对齐、下游接入已在本地实现；生产发布与真实外部配音验收待执行。详见 `EXTERNAL_NARRATION_DELIVERY_2026-10-15.md`。

## 目标与已确定的方向

主流程：确认文案 → 下载朗读稿 → 用户在线下制作最终配音 → 上传纯人声音频 → 文稿核对 → 字词时间对齐 → 字幕与分镜 → 生图 → 预览 → 渲染。

自动配音保留为可选入口。IndexTTS 听感调参暂停；已有参数、样音与云端部署资料保留。当前没有执行云实例关机操作，运行费用状态需单独核实。

最终音频作为时间基准，系统不自动修改其语速、音调或停顿。识别文本仅用于发现差异和获取时间定位；低置信度结果需人工核对，不能直接替换用户确认的文案。

## 仓库核对结果

- `web/components/detail/TtsDetail.tsx` 已有音频播放器、分段与字幕展示，但通过替换 `tts.mp3` 推导字幕路径，需要改成明确的产物引用。
- `web/app/api/manual-upload/route.ts` 已有 Supabase 签名直传，但限定 ingest 阶段；新建针对配音阶段的授权与确认流程。
- `worker/stages/transcribe.py` 已有 faster-whisper 词级时间戳能力，可抽取公用逻辑。现有入口用于原视频逐字稿，外部最终配音不能误走清洗/改写流程。
- `worker/stages/tts.py` 已有语义字幕拆分；外部音频应形成同一类下游产物，采用真实时间戳。
- `worker/stages/image.py` 已有文案字符区间；可关联确认后的朗读稿和音频时间轴。
- `worker/stages/render.py` 已有字幕与镜头时间轴、短叠化和时长校验，需支持版本一致的外部配音产物。
- `worker/db.py` 按阶段顺序领取任务；`rerun_stage` 按阶段序号失效后续阶段。需补充外部配音等待状态和按依赖失效规则，防止排队期间自动生成配音或误重做付费生图。

## 第一阶段：接通上传与等待流程（P0）

1. 在配音阶段提供“自动配音 / 上传外部配音”选择；文案确认后支持下载朗读稿。
2. 外部模式显示“等待上传配音”，不调用 TTS，不自动回退到微软配音。
3. WAV、MP3 直传 Supabase Storage，显示进度、错误与重试；限制文件类型和容量，并通过服务端解码校验实际格式和时长。
4. 每次上传产生独立版本、哈希和存储路径，保留原文件与制作所需标准化副本；不覆盖旧文件。
5. 上传确认校验任务归属、实际存储对象、当前阶段与版本；确认与状态切换原子提交，重复提交幂等，处理中的旧结果不得覆盖新版本。
6. 音频、字幕、对齐报告采用明确产物引用，修正当前文件名推导逻辑。

验收：新建隔离任务能够上传、试听、替换配音；等待期间无自动 TTS 请求；刷新页面仍能恢复状态；未授权用户无法提交或读取配音。

## 第二阶段：文稿核对与真实字幕对齐（P0）

1. 对配音识别并保留原始词级时间戳；将数字、多音字、专名和书名差异列入核对清单。
2. 比较确认稿和实际朗读，区分识别疑似错误、漏读、重复、增词与改词；展示原文、识别内容和对应音频片段。
3. 用户确认最终字幕稿；仅有识别错误时修正字幕文字，实际改词时确认是否同步更新分镜文案。明显差异在确认前阻止付费生图与正式渲染。
4. 使用文本约束对齐和局部重对齐，输出真实字词时间；缺少可靠定位时提示人工修正，不用均匀按字数估算冒充精确时间。
5. 复用语义拆行，保护书名、专名和数字单位。字幕显示区间避开长静音，支持点句试听和修改字幕起止时间。

验收：字幕全文无遗漏、无重复、时间单调且不重叠、不越过音频末尾；抽查开头、中段、结尾与长停顿处，目标字幕边界偏差不超过约 200ms，不能达标的段落明确标记待修正。字符匹配率只作为提示，不能替代听看验收。

## 第三阶段：分镜与生图围绕配音安排（P1）

1. 用户确认文稿差异后再形成分镜；按语义分段决定画面内容，利用真实音频长度决定每个镜头的起止时间。
2. 同一语义段过长时设计多个镜头，过短时合理合并；切换点优先选择句末、转折或自然换气。
3. 复用项目现有生图、九宫格切图和单图替换能力，先展示分镜文本及预计时长，确认后调用付费生图。
4. 配音仅改时长时复用图片并重算时间轴；朗读内容变化时只失效受影响的分镜和图片。保留原始提示词、版本与 Provider task ID。

验收：每个镜头可追溯到文稿区间与音频区间，无黑场与时间缺口；单图替换不触发整批重复生图。

## 第四阶段：剪辑与预览优化（P1）

1. 配音作为剪辑主时钟，不切割重拼配音；镜头运动与短叠化按确认的语义时间点执行。
2. 对短镜头限制转场长度，避免叠化累计导致字幕或画面漂移。
3. 音乐在最终剪辑阶段添加，默认弱于人声；音量调整与峰值处理仅作用于导出副本。
4. 提供含音频、字幕和分镜的预览；字幕、单图、转场修改按最小范围重做。

验收：整片无音频接缝新增卡顿、无明显吞字、无黑帧；字幕与配音保持同步，音视频尾部偏差不超过约 200ms。封面片头存在时，全链路统一应用时间偏移。

## 第五阶段：验收与发布（P0）

1. 先以当前《道德经》第01期文案和用户提供的最终外部配音完成一个隔离任务；新配音尚未提供前，使用现有音频做工程联调并注明其用途。
2. 增加针对上传权限、幂等、音频替换并发、文案差异、字幕边界、下游失效和旧自动配音兼容性的必要测试；执行相关检查与前端构建。
3. 本地完成可试听、可看字幕和可预览成片的结果后，提交具体迁移与部署清单；确认线上变更范围后发布。
4. 保存执行结果、失败原因和恢复步骤到 PROGRESS.md；最终外部音频尚缺失时明确区分工程完成与真实成片验收。

## 执行顺序与交付

按第一阶段 → 第二阶段 → 第三阶段 → 第四阶段 → 第五阶段推进。

第一批交付：外部配音上传入口、等待状态、文件验证与版本管理。

第二批交付：文稿差异核对、逐句试听、真实时间轴字幕。

第三批交付：围绕配音的分镜、生图和完整视频预览。

不设未经实测的完成日期；每批以可操作结果和验收记录报告进度。
