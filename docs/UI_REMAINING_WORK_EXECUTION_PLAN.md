# 页面优化剩余工作执行计划

更新日期：2026-08-11

## 1. 范围与结论

本计划以 `UI_PAGE_WIREFRAME_INDEX.md` 为规划基线，覆盖内容项目、视频采集、任务生产链路、书籍库、音色与声音复刻。

知识图文（`/xhs`、`/xhs/book/[id]`）及其数据模型在当前轮次明确不纳入规划、开发或验收。

当前界面已经具备可运行的任务生产主链路：创建任务、采集、逐字稿、清洗、改写、图片、书籍、配音和成片均有任务详情阶段页面。当前的主要缺口不是再创建一组演示页面，而是：

1. 把采集、书籍、音色三个跨任务运营入口做成真实可用的独立工作台。
2. 补齐任务详情各阶段的人工编辑、恢复和配置能力。
3. 让移动端、数据分页、状态操作和可访问性达到稳定商用的最低标准。

## 3. 实施原则

1. 所有可点击操作必须有真实后端能力；未接通的能力只显示为后续说明，不展示为可用按钮。
2. 复用 `tasks`、`stages`、`artifacts` 及既有 RPC；新增跨任务能力时先补数据库迁移和接口，再做页面。
3. 所有列表采用服务端分页或明确上限，不能无限制一次性读取任务、阶段和 artifact。
4. 桌面端允许宽表横向滚动；移动端使用字段卡片，不强行压缩运营表格。
5. 每个阶段完成后必须运行 `npm run build`；涉及写入或恢复操作时补最小的回归验证。
6. 不修改历史任务的不可变产物。重跑、重生成、二创均创建新版本或从明确阶段恢复。

## 4. 执行阶段

### P0：生产主链路的可控性与异常恢复

目标：让运营人员可以理解任务状态、查看失败原因、从正确断点恢复，避免重复消耗。

工作项：

- 在任务详情增加任务级操作菜单：复制来源链接、取消、查看最近产物、从当前断点继续。
- 为失败阶段统一显示失败原因、最近一次尝试时间、可恢复阶段和重跑影响范围。
- 将已有阶段重跑动作标准化：明确仅重置当前阶段及下游阶段，不重跑上游已完成产物。
- 为任务详情增加采集来源元数据摘要：来源作者、时长、采集时间、互动数据、原始链接。
- 清洗稿支持编辑、保存为人工版本；改写稿的风险位置以正文背景色/下划线标记，并可从建议跳转。

验收标准：

- 失败任务可明确回答“哪里失败、会重跑什么、是否会重复生图/配音”。
- 人工改动的清洗稿和改写稿可保存，后续阶段只读取确认版本。
- 不存在无效的“重启任务”按钮，所有恢复入口均对应实际 RPC 或后端动作。

### P1：视频采集工作台补齐运营能力

目标：将 `/video-collection` 从任务列表提升为可筛选、可调度的采集运营页面。

工作项：

- 增加稳定采集元数据字段和聚合查询：关键词、原始发布时间、描述、作者、粉丝、四项互动数据。
- 逐字稿完成后运行轻量书籍识别，保存候选书名、作者、置信度和识别依据；书籍阶段仅做人工确认，不覆盖早期结果。
- 增加书籍、书名/作者、粉丝、评论、分享、发布时间、任务状态筛选。
- 实现任务多选和真实批量操作：复制来源链接、取消待处理任务；批量重试和断点恢复在后端接口完成后再开放。
- 对单条任务提供状态主操作：查看、去确认、查看异常、查看成片；更多菜单只展示已实现动作。
- 移动端改为字段卡片，保留点赞、评论、分享、收藏四个独立字段。
- 引入分页、加载骨架和 URL 查询参数同步，保证大任务量下可用。

验收标准：

- 任意采集字段均不以示例数据伪造；无数据统一显示“—”。
- 可按书籍和互动数据定位任务，失败任务可直接进入正确恢复点。
- 桌面和移动端均可完整查看独立互动字段。

### P2：书籍库与候选确认抽屉

目标：提供跨任务、按书籍聚合的运营视图，避免从任务标题猜测书籍归属。

工作项：

- 新增 `/book-library` 路由和导航入口。
- 建立书籍聚合查询或物化视图，输出书名、作者、国籍、人工封面、任务数、完成数、运行数、异常数、成片数、最近更新时间。
- 实现书籍搜索、状态筛选、排序、统计卡和分页。
- 实现书籍详情抽屉：关联任务列表、任务状态筛选、打开最近任务、查看成片、进入书籍确认。
- 将低置信度书籍识别在采集页或抽屉内确认，保存人工覆盖值、依据与修改记录。

验收标准：

- 同一本书的多个任务聚合为一条可追溯书籍记录。
- 人工书籍确认不会被后续模型识别覆盖。
- 从书籍库可在两次点击内到达关联任务或最近成片。

### P3：媒体生产工作台的人工控制

目标：把图片、配音、成片三个阶段从“仅查看结果”提升为“有限、可追溯的人工控制”。

工作项：

- 图片：镜头级提示词查看/编辑、单图重生成、违规图生活化替换、备用图片 Provider 切换；保留原图和提示词版本。
- 配音：任务快照内切换 CosyVoice/Edge，选择系统或复刻 Voice ID，试听后确认；支持字幕导出和受控字幕编辑。
- 成片：新任务可选择画面风格、背景音乐和产出数量；背景音乐音量和版权来源可见。
- 成片：展示画面与字幕时间轴，可查看每个镜头对应的字幕和图像，不在历史成片上直接改写。
- 封面：新增视频封面工作台，支持上传/AI 生成封面、封面文字编辑、位置和样式控制、预览和确认。

验收标准：

- 单图、音色、风格、封面修改均只影响当前或新版本任务。
- Edge 可作为人工可选兜底，不能静默覆盖 CosyVoice 结果。
- 成片即使自动质检未通过，仍可预览并允许人工审核通过。

### P4：音色管理与声音复刻闭环

目标：让声音复刻从一次性手工配置变成可管理、可切换的正式能力。

工作项：

- 扩展 `/voice-cloning` 为音色管理页：系统音色、复刻音色、绑定模型、状态、创建时间、试听、默认标记。
- 接入 CosyVoice Voice Enrollment 创建接口，保存 `voice_id`、目标模型、样本来源、展示名称和授权确认。
- 新建音色使用多音色配置表，不再依赖单一环境变量覆盖。
- 支持设置新任务默认音色和 Edge 兜底音色；任务创建时固化音色快照。
- 提供音色启用/停用、删除前二次确认、可用性校验与失败提示。

验收标准：

- 新增音色只需通过管理页提交合法样本 URL 或文件，并能在新任务中选择。
- 复刻音色只用于其创建时绑定的 TTS 模型。
- 任务历史可追溯到实际使用的 provider、model、voice ID。

### P5：体验、性能与验收收口

目标：统一所有非 XHS 页面在桌面、平板、移动端的视觉和操作质量。

工作项：

- 提炼重复的状态徽标、空状态、加载骨架、确认弹窗、表格和详情卡为复用组件。
- 完成键盘操作、焦点顺序、ARIA 标签、对比度和减少动态效果支持。
- 对长文本、超宽表、慢网络、无 artifact、失败重试中等状态补齐 UI。
- 用真实任务数据完成采集、改写确认、图片、配音、成片、人工审核的端到端回归。
- 在桌面、平板和手机视口执行截图验收，修复文本截断、布局溢出、按钮不可达问题。

验收标准：

- 不存在页面空白、数据无限加载、可点击但无效果的控制项。
- 主流程在三类视口均可操作，关键文本不会重叠或被截断。
- 所有新增页面通过构建和最小真实数据验证。

## 5. 推荐执行顺序

1. P0：先把生产错误和人工确认处理清楚，防止消耗重复发生。
2. P1：完善采集运营台，它是所有任务的入口和监控面。
3. P2：建设书籍库，提供跨任务组织能力。
4. P4：完成音色管理，避免继续通过环境变量人工切换。
5. P3：补充图片、配音、成片和封面的可控生产能力。
6. P5：以真实任务做全量回归并完成体验收口。

## 6. 本计划的明确排除项

- 知识图文（XHS）书籍列表和内容工坊不属于当前执行范围。
- 未获得后端能力支持的批量重试、镜头级重生成、风格版本、音色删除等操作，不先以按钮形式上线。
- 历史任务不做静默批量重跑；任何重跑都以明确阶段和影响范围为前提。
