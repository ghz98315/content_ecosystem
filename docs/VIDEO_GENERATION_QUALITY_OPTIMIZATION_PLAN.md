# 视频生成质量优化安排

> 文档状态：已完成本地实现与验证，待部署及真实任务验收  
> 制定日期：2026-08-05  
> 适用范围：短视频主流程 `rewrite -> image -> book -> tts -> render` 及采集评论展示  
> 本轮目标：解决文案不完整、分镜过长、画面静止、成片信息层级不足和评论反馈不足的问题

## 1. 当前问题与目标

当前流程已经可以生成 4:3 图片、配音、字幕和竖版成片，但质量控制仍有以下缺口：

1. 改写提示词将每个候选限制在 150-250 字，可能主动压缩原文；前端默认仅预览前 4 行，用户难以判断实际文案是否完整。
2. 生图阶段按标点切句，长句可能对应一张图片，导致单个镜头停留过久。
3. 成片图片为静态展示，缺少可控的缩放、移动和叠化效果。
4. 书名、作者和免责声明只出现在片头或片尾，正文播放阶段缺少固定信息区。
5. 没有购买意向评论时，购买意向区域为空，热门评论排序也没有充分利用回复数。
6. 改写页面只显示 A/B/C，未直接说明三种候选的创作方向。

本轮完成后，用户应能够先确认完整文案，再确认 24-32 字的分镜和画面动效，最后得到信息固定、镜头节奏稳定的竖版视频。

## 2. 关键产品决策

| 项目 | 推荐默认值 | 可调整范围 |
|---|---|---|
| 改写候选 | 3 个完整候选，尽量保持原文长度 | 后续可增加“只生成一版”以节省成本 |
| 分镜字数 | 目标 28 字 | 24-32 字，最后一段允许更短 |
| 分镜时长 | 平均约 8 秒 | 根据实际 TTS 时间自动微调 |
| 图片动效 | 全片统一缓慢 `Zoom In` | 后续再增加逐图设置 |
| 缩放幅度 | 100%-108% | 首版固定，不开放设置 |
| 叠化时长 | 0.5 秒 | 0.3-0.8 秒 |
| 热门评论排序 | 点赞数 + 回复数 x 5 | 权重后续可配置 |
| 输出画布 | 1080x1920 | 本轮只支持 9:16 |

## 3. 优化一：保证改写文案完整输出

### 3.1 当前原因

- `worker/prompts/rewrite.txt` 要求每个候选只有 150-250 字，原始内容较长时必然被压缩。
- 模型调用没有检查 `finish_reason`，如果模型因输出长度限制而停止，当前流程仍会保存不完整结果。
- 候选依赖文本标签解析，模型格式稍有变化时，可能只解析成一个整体候选。
- 改写页面默认只显示前 4 行，虽然可以展开，但容易被理解为实际只生成了这部分。

### 3.2 改造方案

1. 将“固定 150-250 字”改为“完整表达优先，尽量保持原文长度”。默认目标为原文字数的 90%-110%，如完整表达需要可自然超出，不为满足字数主动删除观点。
2. 完整候选必须包含：开头钩子、核心观点、关键例证或方法、书名/作者事实、自然结尾。
3. 使用结构化 JSON 输出三个候选，减少 A/B/C 标签解析失败。
4. 明确设置足够的输出 token，并检查模型 `finish_reason`。
5. 增加完整性校验：
   - 结尾不是半句话；
   - 不残留“未完”“继续”等截断信号；
   - 候选达到合理最低长度；
   - 原文关键事实至少被覆盖一次；
   - 三个候选均存在且均可独立朗读。
6. 校验失败时自动重试一次，并将失败原因显示在改写阶段，不允许残缺稿进入生图和 TTS。
7. 前端默认展示完整候选，长文放在稳定高度的滚动区，同时显示字数、预计配音时长和完整性状态。
8. 选定候选后允许人工编辑，保存为唯一的 `final_text`；下游只读取 `final_text`，不再自行猜测候选。

### 3.3 A/B/C 显示名称

- `A · 痛点共鸣`：直接切入用户问题，强化情绪共鸣。
- `B · 故事叙述`：通过人物和场景展开，增强代入感。
- `C · 知识科普`：突出观点、方法和信息密度。

### 3.4 验收标准

- 三个候选都能完整展开和复制，不以省略号或半句结束。
- 页面字数与实际 artifact 中的字数一致。
- 模型因长度停止时不会进入下一阶段。
- 用户修改后的最终稿与 TTS、字幕、分镜使用的文本完全一致。

## 4. 优化二：按 24-32 字生成约 8 秒分镜

### 4.1 切分规则

1. 先按句号、问号、感叹号划分完整语义。
2. 超过 32 字的句子，再按逗号、分号和语义边界拆分。
3. 少于 24 字的短句优先与相邻句合并，但合并后不得超过 32 字。
4. 不拆开书名、人名、数字、固定词组和完整引用。
5. 目标值为 28 字；最后一段允许少于 24 字。
6. 生图前生成明确的 storyboard 数据，每个分镜包含文本、字数、预计时长、图片和动效。
7. TTS 完成后按实际音频边界校准镜头时间，不再简单平均分配总时长。

### 4.2 生图页面

每个分镜显示：

```text
分镜 03 | 29 字 | 预计 8.2 秒 | Zoom Out
对应文案：……
对应图片：……
```

### 4.3 验收标准

- 除最后一段外，至少 90% 分镜位于 24-32 字。
- 平均镜头时长约为 8 秒，不出现无理由的超长静止镜头。
- 图片数量与分镜数量一致。
- 画面切换与配音语义边界基本一致。

## 5. 优化三：统一图片动效与叠化转场

### 5.1 首版动效

- 首版全片统一使用缓慢放大 `Zoom In`。
- 每个镜头从 100% 缓慢放大到 108%。
- 本轮不提供逐张动效选择器，也不引入其他移动方向。
- 动效作为渲染模板默认值实现，不要求用户额外设置。

后续在渲染基础稳定后，再把 `Zoom Out`、上下左右移动和静态效果前置到分镜页面，支持逐张设置。storyboard 数据结构会预留 `motion` 字段，避免后续增加设置时再次改造产物格式。

### 5.2 转场

- 默认使用 0.5 秒叠化。
- 叠化时间计入镜头总时长，不能造成音画累计偏移。
- 第一张图淡入，最后一张图淡出，中间镜头交叉叠化。
- 本轮不增加花哨转场，避免影响内容阅读。

### 5.3 验收标准

- 动效不露黑边、不拉伸图片、不产生明显跳帧。
- 所有正文镜头都使用统一的缓慢 `Zoom In`，速度平稳一致。
- 叠化后总视频时长与音频时长保持一致。

## 6. 优化四：固定书名、作者和免责声明版式

主视频仍输出 1080x1920，正文阶段采用固定布局：

```text
顶部：书名 + 作者
中部：4:3 动态图片
下部：动态字幕
底部：固定简短免责声明
```

推荐免责声明：

> 内容基于书籍及相关资料整理，仅供参考，不构成专业建议。

实施规则：

- 书名和作者必须经过书籍阶段确认后才能渲染。
- 4:3 图片完整展示，不裁成竖图。
- 字幕不覆盖图片主体，也不与免责声明重叠。
- 固定使用简短免责声明，取消重复的长片尾免责声明。
- 片头书名卡先保留，首版时长为 1.5 秒。
- 长书名和长作者名必须自动换行或缩小到安全字号。

验收时检查 1080x1920 成片以及手机端播放，不允许文字越界、重叠或被平台控件遮挡。

## 7. 优化五：评论的购买意向与热门降级展示

### 7.1 展示逻辑

- 存在购买意向评论：优先展示购买意向评论，并保留热门评论区。
- 不存在购买意向评论：显示“暂无明确购买意向，以下为热门评论”。
- 热门评论按 `点赞数 + 回复数 x 5` 综合排序，最多展示 10 条。
- 过滤空评论、重复评论和纯表情评论。
- 展示点赞数和回复数，让用户理解排序依据。

### 7.2 验收标准

- 没有购买意向时页面不再只显示空状态。
- 高回复评论即使点赞不是最高，也能进入热门列表。
- 同一条评论不会在两个区域重复出现。
- 评论采集失败与评论确实为空必须显示不同状态。

## 8. 推荐实施批次

### 批次 P0：完整文案与唯一最终稿

范围：改写提示词、结构化输出、截断检测、完整性校验、完整展示、人工编辑和 `final_text`。  
原因：分镜、配音和图片都依赖最终文案，必须先稳定文本源。  
状态：已实现，本地验证通过，待线上真实模型输出验收。

### 批次 P1：分镜算法与分镜确认

范围：24-32 字切分、预计时长、storyboard 产物、生图页面分镜信息。  
依赖：P0 的唯一最终稿。  
状态：已实现，分镜单元测试通过，待线上真实生图验收。

### 批次 P2：动效、叠化与固定视频版式

范围：全片统一缓慢 `Zoom In`、0.5 秒叠化、保留 1.5 秒片头书名卡、顶部书籍信息、字幕区、底部简短免责声明。  
依赖：P1 的 storyboard 和现有 4:3 图片。  
状态：已实现，FFmpeg 合成烟测通过，待线上完整成片验收。

### 批次 P3：评论降级与改写标签完善

范围：热门评论综合排序、空状态降级、去重、A/B/C 可读名称。  
特点：与视频渲染耦合较低，可独立发布。  
状态：已实现，排序单元测试及前端构建通过，待线上评论样本验收。

### 批次 P4：完整回归与线上验收

至少使用 3 个真实任务：短文案、中等文案、较长文案。逐项记录文案完整度、分镜字数、镜头时长、动效、叠化、固定文字、评论展示、字幕同步和最终视频时长。

## 9. 本轮明确不做

- 不扩展小红书流程。
- 不增加自动发布到视频平台。
- 不引入复杂模板市场或大量转场特效。
- 不在本轮增加多轨时间线编辑器。
- 不修改已完成任务的历史产物；新逻辑通过新任务或明确重跑生成。

## 10. 已确认决策

1. 完整改写稿尽量保持原文长度，以完整表达为先，同时显示字数和预计配音时长。
2. 固定免责声明采用简短版本：`内容基于书籍及相关资料整理，仅供参考，不构成专业建议。`
3. 片头书名卡先保留，首版按 1.5 秒实现。
4. 首版动效只实现一种，全片统一缓慢 `Zoom In`；逐图动效设置放到后续迭代。

## 11. 开发素材卡

- 阶段：规划阶段。
- 本轮主题：从“能够生成视频”进入“文案、分镜、画面和反馈都可控”的质量优化。
- 关键模块：完整文案、语义分镜、图片动效、固定版式、评论反馈。
- 解决的问题：下游流程使用不完整文本、镜头过长和成片信息层级不足。
- 用户可感知变化：能够确认完整稿件、查看每个分镜，并获得统一平稳的图片动态效果。
- 关键设计决策：先稳定与原文长度接近的唯一最终稿，再建立 storyboard，最后以统一 `Zoom In` 改造渲染。
- 验证证据：新增能力已完成本地实现、单元测试、前端构建和 FFmpeg 烟测，尚未完成线上真实任务验收。
- 可写角度：AI 视频生成的质量瓶颈不只在模型，而在每个中间产物是否完整、可见、可确认。
