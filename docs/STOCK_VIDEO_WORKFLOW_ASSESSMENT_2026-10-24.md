# 视频素材拼接模式：评估与实施方案

日期：2026-10-24。状态：完成开源调研与本地概念样本；尚未改动线上生产流程。

## 结论

可行。建议新增“视频素材”视觉模式，与“AI 图片”模式并列；复用现有生产线的采集、清洗、二创、配音、字幕、发布包与成片能力。国学、健康、城市场景是内容类别，图片或视频是画面来源，两者独立配置。国学可以使用国学图片，也可以使用实拍素材；城市场景同样如此。

不建议复制一整套生产线，也不建议把现有生图处理器改成同时承担搜索、下载、视频裁剪的混合处理器。新增独立素材处理器与视频时间线，由统一成片入口分派。现有任务默认继续使用 AI 图片，已有规则快照不可被切换覆盖。

## 需求理解

以配音的实际时长为总时长，画面按段落主题近似匹配，不要求每句话对应一个精确镜头。字幕仍跟随实际配音；本方案放宽的是画面与解说逐句卡点的要求。先做纯视频素材模式，素材不足时扩大检索、复用适当的已授权镜头或允许手动补充，不自动产生付费生图。

2026-10-24 用户确认补充：每个画面段落目标覆盖 80–100 字，减少切换；选定视频必须先列出供用户确认，确认后才启动正式拼接。以下流程与剪辑规则以此为准。此前 24 秒概念样本仅验证技术链路，不作为镜头频率模板。

## 本地样本结果

- 主题：给生活留一点余地，采用自行编写的三段短文。
- 2 个网络视频来源，3 个截取镜头，原素材声音移除；新配音采用 Edge TTS。
- 成片：24.29 秒，720×1280，约 4.20 MiB；方形主画面与模糊背景、顶部标题、字幕、素材署名。
- 脚本记录：下载 6.23 秒，配音 6.13 秒，渲染 10.17 秒，总计 22.62 秒。**不包含人工搜索、授权核查和样本程序编写时间**，不用于直接推算长视频耗时。
- 字幕按每句配音时长分配、每条不超过 12 字，只用于概念预览；生产接入继续使用现有音频对齐能力。
- 素材检索和语义挑选由人工完成，尚未接入自动素材 API、视觉重排和生产数据库。
- 本样本没有背景音乐，正式模式复用现有配乐设置和音量。
- 成片完成全片解码检查，退出码 0、无解码错误；已检查预览帧。瀑布原片有明显景深虚化，说明生产选片还需要清晰度筛选，不能只核对分辨率数字。
- 文件：`worker/output/stock-video-evaluation-20261024/sample.mp4`；实测参数及来源：同目录 `evaluation.json`。

## 开源组件选择

1. [MoneyPrinterTurbo](https://github.com/harry0703/MoneyPrinterTurbo)，MIT。最接近目标，包含关键词找素材、素材下载、时长裁剪和合成等能力。参考其素材服务与来源记录设计，第一阶段不整体引入它的 Web、文案、配音和任务体系，避免和现有系统重复。
2. [PySceneDetect](https://github.com/Breakthrough/PySceneDetect)，BSD-3-Clause。负责长素材的镜头边界检测，避免跨越原片切镜截取；它不负责理解画面或网络搜索。短素材第一版可以暂不启用。[官方文档](https://www.scenedetect.com/docs/latest/)。
3. [OpenCLIP](https://github.com/mlfoundations/open_clip)。适合第二阶段做抽帧与文字的语义排序；需另行核对所选模型权重的许可和中文能力，可采用中英双语关键词。先用 API 元数据筛选，抽帧检查最终候选，避免一开始部署重模型。
4. [FunClip](https://github.com/modelscope/FunClip)，MIT。适合按原视频中的讲话内容剪辑访谈、演讲；本需求以无声配画素材为主，首版不作为核心依赖。

上述代码许可和具体视频素材的授权分别记录；不能因为下载器开源，就默认所有可下载视频均可用于带货视频。

## 素材来源与实际接入条件

- 优先：自己的实拍或已授权素材库、本地文件夹、手动上传。适合高校、城市等精确实体；必须保留来源与授权记录。
- 在线自动检索：先接 [Pixabay API](https://pixabay.com/api/docs/) 或 [Coverr API](https://coverr.co/developers)。两者都需要自己的 Key；当前项目未发现这两家的已配置 Key。
- Pixabay 要求请求缓存 24 小时，限制系统化批量下载；采用按任务需要的小规模检索，不全站扫库。
- Coverr 页面当前提供每小时 50 次免费调用；具体下载额度和用途以实际账号套餐及许可为准。筛选 Original Stock，符合本次实拍目标。
- [Pexels 官方 API 页面](https://www.pexels.com/api/)目前显示暂停发放新 Key；已有有效 Key 可作为补充，不能作为必须依赖的新用户入口。
- Wikimedia Commons 可作公开许可素材的补充与无 Key 验证来源，但每条文件许可不同，不能统一视为 CC0；下载速度和题材覆盖需要实测。
- 抖音、视频号、B站等普通搜索结果不进入默认自动素材池。现有采集能力可用于用户有权使用的指定视频导入；公开播放、下载成功不等于获得商用授权。

题材覆盖预判：自然、生活、运动等宽泛主题更易获得素材；中国具体校园、城市地标、古代人物事件更依赖自有或特定授权库。涉及深圳、某高校的事实性描述，要匹配真实地点，不能用相似外国建筑冒充。

## 建议的生产流程

1. 保持采集、清洗和二创规则；创建任务时增加画面模式选项。
2. 确认文案后，按完整语义划分约 80–100 字的画面段落，不截断句子、不遗漏文案；末段可以不足 80 字。提取主题、人物、地点、动作和禁用内容，生成中英检索词；检索关键词不需要上传完整文稿。
3. 配音上传或生成，确定总时长。素材搜索可以提前进行，最终时间线按配音时长收口。
4. 每个语义段落先检索 5–10 个候选，只下载筛选后的少量素材；优先适配比例、清晰、无硬字幕、没有明显水印的片段。
5. 对候选抽帧，核对主题、地点和人物是否合适，排除黑屏、重复、明显水印或错误实体；不以“标题含关键词”作为匹配通过标准。
6. 先展示“视频素材确认清单”：每段的完整对应文案、字数、配音实际时长（尚无配音时明确标注预估）、首选视频预览、来源链接、源片总长、拟截取起止、可覆盖时长、实际像素、匹配理由及许可信息。每段主推 1 条，可展开 1–2 条备选，提供单段换片、锁定和全部确认。
7. 设立独立的“待确认素材”节点：完成检索后停在此处。用户可一次确认整份清单；确认后才编排并拼接正式视频。候选预览和必要的下载检查可以提前完成，不提前生成整条预览片。确认绑定具体素材与截取范围；用户换片或系统替换素材后，对受影响段落重新确认，不能静默替换。
8. 最终渲染使用原分辨率素材，加入现有字幕、标题、脚注、配乐和发布包；完成自动检查及耗时统计。

## 首版剪辑规则

- 以每段 80–100 字规划画面，每段优先 1 条连续视频覆盖；时长跟随实际朗读速度与停顿，不写死为某个秒数。素材自身含频繁切镜也会影响体验，选片时需检查连续稳定画面长度。
- 优先找足够长的连续镜头。若源片不足以覆盖整段，先换更长素材；仍不足时，可提议 2 条风格与主题一致的视频共同覆盖该段，在确认清单中说明后由用户确认。不得为了凑时长默认反复循环、冻帧、倒放或大幅慢放。
- 在尚无配音时，按计划语速估算素材需求并留余量；配音完成后核对实际覆盖时长，不足则补充候选并重新确认受影响段落。
- 长素材可取多个不重叠片段，但相邻镜头不重复同一画面；记录复用率，尽量避免短时间内反复出现同一段。
- 切镜靠近段落或语句结束处，不逐字匹配。原素材音频默认移除，统一使用配音和配乐。
- 默认直接切换，必要时提供一种短叠化；叠化重叠量必须计入时间线，防止成片越拼越短。
- 画面不足时先换候选；不默认冻帧、来回倒放或过度慢放凑时长。
- 实拍视频默认保留自身运动，不再套图片的放大缩小运镜，以免产生额外抖动。
- 输出保持 9:16 外框。主画面比例和模糊填充继承内容模板：国学按当前 1:1 主画面规则；城市场景可采用全屏或保留横幅画面，作为独立模板配置。
- 国学标题字号、颜色和相对主画面位置继续沿用已有模板；实拍模式脚注使用素材说明，不能照搬“图片由 AI 生成”。

## 隔离、复用与重跑

- 任务快照分别保存内容类别、画面模式、素材策略与版本；既有图片任务不自动迁移。
- 不把视频文件登记为图片，统一视觉清单明确区分 image/video；成片入口按类型处理。
- 新增素材台账，保存来源页、供应商素材 ID、作者、许可、下载时间、校验和、实际像素和时长；剪辑时间线另存 JSON。
- 修改配音或音量：复用已选视频，重新计算镜头时长、对齐字幕并成片。
- 修改少量文案：优先保留锁定镜头，只补充受影响段落；重跑成片不触发网络重新选片。
- 单镜替换：仅下载新镜头并重跑成片。网络重试保留已成功素材，避免整条重来。
- 旧素材已清理时，按供应商 ID 尝试重新下载；链接失效时明确展示缺失镜头，不静默改用无关素材。

## 存储与效率

素材视频通常比图片占空间，不建议全部存入当前 Supabase Storage。Supabase 保存任务、来源和时间线；源片及缓存优先放本地 Worker 专用目录，后续可切换 R2。源片不上传 Git。

任务下载缓存建议 48 小时和容量上限双重控制，只清理未被正在运行任务占用的内容；精选授权素材库单独管理，不与任务缓存一起清除。成片沿用 7 天保留规则。缓存淘汰后仍保留素材元数据与剪辑方案。

性能主要来自检索和下载、抽帧筛选、解码缩放和编码。去掉生图等待及图片运镜会节省部分时间，但实拍下载、帧率转换和高码率素材会引入新开销，不能承诺一定比当前快。首版限制 1080p/30fps、少量并发下载、缓存复用、仅转码一次，避免 CPU 与现有成片并行争抢。12 分钟视频在 20 分钟内完成作为验收目标，需扣除人工时间并在当前机器上实测。

## 分阶段实施与验收

第一阶段：新增独立视觉模式、一个在线供应商和本地素材导入；按 80–100 字划分画面段落，完成关键词检索、来源台账、素材确认清单与待确认节点、时长编排及现有模板合成。先做生活/自然题材 1 分钟，再测具体城市题材覆盖率。

第二阶段：抽帧视觉重排、镜头边界检测、去重、换词重搜、多供应商回退和单镜替换；增加锁定镜头与来源展示。

第三阶段：12 分钟长视频和两任务并发验收，测试网络中断后恢复、素材过期与重新获取、配音修改复用、清理保护及各内容模板互不干扰。

验收标准：
- 实拍素材可追溯，无未知授权素材进入自动发布包。
- 未确认素材清单时不启动正式拼接；确认后复用已锁定素材，候选变更需重新确认受影响段落。
- 每个画面段落以 80–100 字为目标，保持文案完整；优先 1 条连续视频覆盖，素材不足的组合方案明确展示后确认。
- 成片总长与配音差异不超过 0.2 秒；结尾无缺音、长黑屏或异常冻帧。
- 字幕按现有规则跟随配音，每条不超过 12 字。
- 明确实体的镜头不使用其他城市或学校冒充，泛主题画面由人工抽查相关性。
- 重跑成片及修改配音时复用锁定素材，不重复进行付费生图。
- 下载、匹配、编排、成片各自记录耗时，首次下载与缓存命中分别统计。
- 既有 AI 图片模式与国学、健康、场景规则通过原有回归检查。

下一步正式搭建只需接入一个可用素材 Key，或先使用本地授权素材库；当前样本不代表自动检索模块已经上线。
