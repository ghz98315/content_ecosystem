# 逐字稿与清洗稿工作台 ASCII 线框图

> 状态：细化规划稿
>
> 参考：`ref-doc/ref-page/02.png` 的工作台层级与当前八阶段流程。
>
> 本文只确认页面结构、字段和交互，不修改网页代码、数据库或 Worker。

## 1. 页面定位

逐字稿和清洗是连续的两个处理阶段，但页面可以整合为一个“文本审阅工作台”：

- 逐字稿负责展示 ASR 原始结果、时间信息和识别状态。
- 清洗稿负责修错字、断句、数字规范、删减口头冗余和合规替换。
- 两个阶段共享同一页面上下文，不需要用户在两个路由之间来回跳转。
- 清洗稿确认后才允许进入改写；未确认时不能被后续阶段误读为最终文案。
- 页面沿用 `02.png` 的工作台外壳，但正文改为文本对照布局，而不是采集数据表格。

## 3. 页面层级

### 3.1 全局层

- 使用与采集页、书籍库一致的顶部导航、工作区状态和返回行为。
- 页面标题必须直接说明当前工作：“逐字稿与清洗稿”，不使用营销式大标题。
- 任务标题、作者、时长和任务 ID 作为上下文信息，避免用户误操作到其他任务。

### 3.2 阶段层

- 顶部阶段进度条显示八阶段状态；当前阶段高亮，后续阶段置灰。
- 已完成逐字稿但清洗失败时，原始逐字稿仍可查看，清洗区显示失败原因和重试入口。
- 清洗完成但未确认时，改写阶段显示锁定状态，不允许绕过确认直接推进。

### 3.3 内容层

- 桌面端左右双栏：左侧原始逐字稿，右侧清洗后文案。
- 两栏顶部工具栏独立，避免“复制原文”和“保存清洗稿”混淆。
- 两栏正文滚动互不影响；启用“同步滚动”时按段落锚点同步，而不是按滚动百分比粗略同步。
- 移动端上下堆叠：先原始逐字稿，再清洗稿；顶部提供“原文/清洗稿”分段切换，避免两栏过窄。

## 4. 逐字稿区

逐字稿区是只读审阅区，原始 ASR 结果不能被清洗操作覆盖。

字段与操作：

- 原始文本总字数。
- 分段时间戳；有词级时间戳时支持点击文本跳转音频位置。
- 音频播放、暂停、拖动和当前时间显示。
- 复制全文、下载原始 JSON/文本。
- “显示时间戳”开关；默认按自然段阅读，按时间模式显示分段。
- ASR 异常提示，例如空文本、时间戳缺失、语言识别不确定。

## 5. 清洗稿区

清洗稿是可编辑的候选产物，保存和确认必须分开。

- 默认显示清洗后的完整文案，不再强制用户先阅读原始稿。
- 每个修改片段带连续编号，例如 `①`、`②`、`③`，与下方检查建议一一对应。
- 修改内容使用浅色底纹或下划线标记，删除内容不直接出现在最终文本中。
- 点击编号，右侧或下方检查详情定位到对应文本位置；点击建议也能反向定位文本。
- 支持人工编辑、撤销、重做和保存草稿。
- 保存草稿只更新当前清洗版本，不触发改写、生图或配音。
- “确认清洗稿并继续改写”才写入确认状态并解锁 rewrite 阶段。

## 6. 清洗规则和检查摘要

检查摘要固定在正文下方，避免用户滚动到顶部才能判断是否可以放行：

| 检查项 | 展示内容 | 未通过动作 |
| --- | --- | --- |
| 字数变化 | 原文、清洗后、增减比例 | 显示异常扩写原因，禁止自动放行 |
| 断句质量 | 过长句、孤立短句、标点异常 | 定位到具体段落 |
| 数字朗读 | 10→十、3.0 等特殊格式 | 显示模型判定和可编辑结果 |
| 健康合规 | 命中词、建议替代表达 | 使用中性改写，不使用谐音规避 |
| 书名格式 | 统一为《书名》 | 定位并提供一键修正 |

清洗异常时保留异常稿供人工查看，但不允许系统把它当作已确认清洗稿继续下游阶段。

## 7. 操作栏和状态

```text
逐字稿完成、清洗处理中       [查看原文] [暂停后续]
清洗完成、待人工确认         [保存草稿] [确认清洗稿并继续改写]
清洗失败                     [查看错误] [重新清洗]
清洗已确认                   [查看改写稿] [重新打开清洗稿]
```

- 主按钮始终只有一个，随阶段状态变化。
- “重新清洗”必须明确从 clean 阶段重新执行，并提示会使下游未确认阶段失效。
- 已确认清洗稿重新打开编辑时，必须创建新版本或要求明确“修改并重新放行”，不能静默覆盖历史确认版本。

## 8. 与后续阶段的边界

```text
transcribe done
      ↓
clean pending/running
      ↓
clean draft ──保存草稿──> clean draft（不解锁下游）
      ↓
确认清洗稿
      ↓
rewrite pending（读取 confirmed clean version）
```

- rewrite 只能读取 `confirmed clean version`，不能读取临时编辑内容或异常稿。
- 书籍识别可在逐字稿完成后异步开始，但书籍确认信息独立保存，不覆盖清洗文本。
- 重新清洗、重新改写和重新成片的失效范围必须在确认弹窗中明确展示。

## 9. 响应式与视觉规范

- 桌面 `>=1200px`：左右两栏各占约 50%，中间保留 16-24px 呼吸间距；正文区域固定最小高度，顶部操作不随内容跳动。
- 平板 `768-1199px`：左右两栏可调整为 45/55 或上下切换，检查摘要保持全宽。
- 手机 `<768px`：上下堆叠，使用阶段切换和折叠检查项；主确认按钮固定在底部安全区。
- 延续采集页的浅色背景、低饱和状态色、8px 以内圆角和轻阴影；修改高亮不能使用刺眼红色。
- 加载使用骨架屏；切换原文/清洗稿和定位修改处使用 150-220ms 的淡入和位移动画，保持“呼吸感”但不影响阅读。

## 10. 当前结论

逐字稿和清洗稿可以按照 `02.png` 的工作台框架整合，但整合的是页面层级和操作逻辑，不是把文本内容做成采集页那种宽表格。

推荐最终结构：

1. 复用顶部导航、任务上下文和阶段进度条。
2. 中央采用原始逐字稿 / 清洗稿左右对照编辑区。
3. 下方固定显示字数、合规、数字和书名格式检查摘要。
4. 以“保存草稿”和“确认清洗稿并继续改写”区分临时编辑与正式放行。
5. 桌面左右对照，移动端上下堆叠，确保同一套文案在不同设备上都可读、可审、可追溯。
