# Worker 启动网络恢复

## 故障

《道德经》任务的生图阶段停留在 processing。登录后启动的 Worker 在恢复过期任务时遇到代理连接拒绝，异常发生在原有循环保护以外，导致进程退出。

## 修复

- 将启动恢复纳入轮询的网络异常保护；启动恢复成功之前不认领新阶段。
- 网络连接失败后重建数据库客户端，以 2、4、8、16、30 秒退避重试，最大等待 30 秒。
- 隔离 Worker 的完成状态检查也纳入异常保护，避免完成检查时断网导致退出。
- 常驻 Worker 异常退出后，启动器等待 30 秒自动拉起；正常退出和任务隔离模式不自动重启。
- 启动器在再次启动前保存前一轮输出和错误日志，保留故障证据。

## 验证

- 新增 3 项模拟断网、状态检查断网及有上限退避测试。
- 全部 200 项 Python 测试通过。
- PowerShell 启动器语法检查通过。
- 生产任务只读预检：35 个分镜、最多 4 张九宫格，已有图片和 provider job 记录均为 0。

## 当前恢复条件

用户已明确授权：按现有提示词、九宫格方式直接付费生图，不设置费用上限，后续同类生成无需重复询问费用上限。本次沿用 APIMart（api.apib.ai）与 gpt-image-2，35 个分镜最多生成 4 张九宫格源图，保留已确认文案和配音。若改变服务、模型、生成方式或扩大任务范围，需重新核对用户意图。

本次没有修改模型配置、文案或已确认配音。

## 实际恢复时追加修复

- APIMart 国内端点 `api.apib.ai` 直连正常，系统代理会导致 TLS EOF。提交和轮询现在共用明确的网络策略，默认对该国内端点直连，HTTPS 校验保持开启。
  如确需继承系统代理，可在 Worker 环境中显式设置 `APIMART_IMAGE_TRUST_ENV=true`；不影响 Supabase 或其他服务的网络策略。
- 当前 SDK 返回 `httpx2.URL`，原类型判断误将异步 APIMart 当作同步接口。现在按 URL 值判断，正确保存 provider task ID 后轮询。
- APIMart 输出图片下载沿用该直连策略，网络重试会复用已保存的任务，不重新生成。
- 首次 SDK 类型不兼容造成一笔 0.0085 美元的成功计费请求未被程序保存任务编号，无法从公开查询接口自动取回。已向用户说明，保留异常记录；后续修复的作业均保存编号。
- 最终完整回归：203 项测试通过。
