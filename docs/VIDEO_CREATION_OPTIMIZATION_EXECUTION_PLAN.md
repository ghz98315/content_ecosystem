> 项目：AI 图书带货视频创作台  
> 文档状态：执行中

> 次阶段：验收准备  
> 制定日期：2026-08-04  
> 适用范围：短视频创作主链、共享页面框架；小红书模块仅在主链稳定后统一视觉

## 1. 文档目的

本文档用于指导短视频创作台按小批次在线优化，避免一次性重构带来的回归风险。

每个批次都必须满足以下条件：

1. 目标、范围、非范围和验收标准明确。
2. 可独立开发、独立部署、独立线上验收。
3. 数据变更向后兼容，失败时可以回退上一线上版本。
4. 用户能够感知本批次解决了什么问题。
5. 上线后留下测试任务、截图、结果和已知边界。

本文档既是执行顺序，也是后续进度记录入口。开始某批次前，将状态从 `待开始` 改为 `进行中`；验收后改为 `已上线并验收`。

## 2. 当前基线

### 2.1 已有能力

- 已实现 `ingest → transcribe → clean → rewrite → image → book → tts → render` 八阶段处理器。
- 前端已有任务列表、阶段进度条、阶段详情、评审门、产物预览和成片下载。
- Supabase 已承载任务、阶段、产物、Storage 和 Realtime。
- 本地 Python Worker 已承载采集、ASR、LLM、生图、TTS 和 FFmpeg 渲染。
- 前端生产构建已通过，Python 源码编译已通过。

### 2.2 当前边界

- `待验证`：仓库内没有完整真实样片和端到端验收记录。
- 采集实际为“自研解析 + 手动上传”，第三方 API 降级尚未接入。
- 改写候选可以选择，但不能直接编辑为最终稿。
- 生图可以查看，但不能单图重生成、替换或调整裁切。
- TTS 主要提供句级时间戳，不是完整词级字幕编辑能力。
- 方形图片使用黑边填充为 9:16，成片观感待优化。
- 镜头时长按图片数量平均分配，没有按字幕语义时间切换。
- 上游阶段重跑时，下游阶段和旧产物不会自动失效。
- 缺少统一的耗时、模型成本、人工介入和失败原因记录。

### 2.3 当前阶段判断

当前不是继续扩功能数量的阶段，而是：

> M8 已实现，进入真实链路验收、创作控制能力补齐和 M9 质量打磨阶段。

### 2.4 数据平台决策门

Supabase 免费项目数量或用量限制已经成为 B0 的新增架构约束。B1 之前必须先完成数据平台选择，避免页面重构后再次改写认证、状态刷新和数据访问。

决策与迁移执行方案见：`docs/DATA_PLATFORM_MIGRATION_DECISION.md`。

当前允许继续：基线、文档、测试和供应商无关的 API 边界设计。  
当前暂停：新数据库依赖、正式数据迁移和 Production 环境切换。

## 3. 总体目标与成功标准

### 3.1 产品目标

将当前“能跑流程的工程界面”升级为“可以长期反复使用的短视频创作工作台”。

用户在任意阶段都应能清楚回答：

- 当前输入是什么？
- 系统做了什么？
- 结果是否可信、是否可编辑？
- 当前为什么被阻塞？
- 下一步应该点击什么？
- 重跑会影响哪些下游结果？

### 3.2 首轮成功标准

- [ ] 使用 5 条真实视频执行完整验收。
- [ ] 至少 4 条完成从链接到 `final.mp4` 的完整链路。
- [ ] 至少 3 条经人工确认后达到可发布标准。
- [ ] 所有阶段都有明确的输入、输出、状态、异常和下一动作。
- [ ] 改写稿、书籍信息、字幕、单张图片均可人工修正。
- [ ] 上游重跑不会继续使用旧下游产物。
- [ ] 成片没有明显黑边、字幕遮挡、文字越界或音画错位。
- [ ] 桌面端和移动端不存在内容重叠或主要操作不可达。
- [ ] 每条验收视频有总耗时、阶段耗时、成本和人工介入记录。

### 3.3 本轮明确不做

- 不先做批量链接和高并发队列。
- 不先做四种以上模板矩阵。
- 不先做自动发布到内容平台。
- 不承诺模型生成内容完全正确。
- 不在短视频主链稳定前大幅扩展小红书业务功能。
- 不为了视觉效果引入与现有技术栈不匹配的重型框架。

## 4. 执行原则

### 4.1 小批次线上发布

标准发布链路：

```text
确认批次范围
  → 本地实现
  → 静态检查和构建
  → Vercel Preview
  → Preview 冒烟验收
  → Production 发布
  → Production 固定任务复测
  → 更新进度和证据
```

禁止将多个高风险链路合并为一次发布。例如，数据库迁移、重跑语义、渲染算法和全站视觉重构不得在同一个批次同时上线。

### 4.2 数据安全

- 所有数据库迁移必须向后兼容。
- 旧字段先保留，至少经过一个稳定批次后再评估删除。
- 生成产物优先采用版本化，不直接无提示覆盖。
- 上游重跑前必须展示影响范围。
- Production 不使用临时测试 SQL 修改正式数据结构。
- 不在日志、截图或进度文档中记录密钥和敏感用户数据。

### 4.3 完成定义

一个批次只有同时满足以下条件才算完成：

- [ ] 功能按范围实现。
- [ ] 空态、加载态、失败态、禁用态和成功反馈完整。
- [ ] 本地构建和类型检查通过。
- [ ] Preview 环境验收通过。
- [ ] Production 环境固定路径复测通过。
- [ ] 已知边界已记录。
- [ ] `PROGRESS.md` 和本执行文档状态已同步。

## 5. 视觉与交互规范

### 5.1 视觉方向

定位为安静、专业、适合重复工作的内容运营工具，不采用营销落地页风格。

- 页面背景：中性浅灰。
- 内容工作区：白色或接近白色。
- 主文字：接近黑色的中性深色。
- 主操作：稳定蓝色。
- 强调色：少量橙色，用于需要人工介入的提示。
- 完成：绿色；警告：橙色；失败：红色；等待：灰色。
- 避免大面积渐变、装饰光斑、超大标题和无意义插画。
- 卡片圆角不超过 `8px`，禁止卡片内继续嵌套装饰卡片。

### 5.2 基础尺寸

| 元素 | 建议值 |
|---|---:|
| Sidebar 展开宽度 | 232px |
| Sidebar 收起宽度 | 56px |
| 主内容最大宽度 | 1440px |
| 页面横向内边距 | 24px；移动端 16px |
| 标准输入框高度 | 40px |
| 主按钮高度 | 40px |
| 图标按钮 | 36px × 36px |
| 阶段节点最小宽度 | 96px |
| 常规圆角 | 6px |
| 模态框圆角 | 8px |
| 正文行高 | 1.65-1.8 |

字体大小不随视口宽度缩放，使用固定的层级体系：

- 页面标题：24px。
- 区域标题：18px。
- 面板标题：15-16px。
- 正文：14px。
- 辅助信息：12px。

### 5.3 统一组件

批次 1 必须形成以下公共组件或等价的统一实现：

- `Button`：primary / secondary / danger / ghost / icon。
- `Input`、`Textarea`、`Select`、`Checkbox`、`SegmentedControl`。
- `StatusBadge`、`StageStatus`、`ProgressIndicator`。
- `Tooltip`、`Toast`、`Modal`、`ConfirmDialog`。
- `EmptyState`、`ErrorState`、`Skeleton`、`InlineNotice`。
- `SectionHeader`、`Toolbar`、`MetadataList`。
- `AudioPlayer`、`VideoPreview`、`ArtifactPreview` 的统一外壳。

熟悉的操作优先使用图标：返回、重试、编辑、保存、下载、播放、暂停、放大、删除；不熟悉的图标必须有 Tooltip。

### 5.4 响应式规则

- `≥ 1280px`：展开 Sidebar，任务内容采用主工作区 + 辅助信息双栏。
- `768-1279px`：Sidebar 可收起，详情面板保持单列或窄双栏。
- `< 768px`：Sidebar 改为抽屉，阶段条改为纵向列表或横向可滚动列表。
- 固定比例媒体必须使用 `aspect-ratio`，禁止内容加载后撑开布局。
- 所有工具栏允许合理换行，不允许按钮覆盖标题或状态。

### B12：重跑、版本和异常恢复

**目标**：确保线上反复优化时不会混用新旧产物。

**核心规则**：

```text
重跑 clean  → rewrite/image/book/tts/render 失效
重跑 rewrite → image/book/tts/render 失效
重跑 image   → render 失效
重跑 book    → tts/render 失效
重跑 tts     → render 失效
```

**工作内容**：

- [ ] 点击重跑前展示受影响的下游阶段。
- [ ] 用户确认后原子更新相关阶段状态。
- [ ] 旧 artifact 保留版本，但不再作为当前版本读取。
- [ ] 阶段增加有限次数自动重试和明确的手动重试。
- [ ] 区分网络错误、模型错误、输入缺失和 FFmpeg 错误。
- [ ] Worker 认领任务增加并发安全和幂等保护。
- [ ] 任务取消后允许查看既有产物，但不再继续处理。

**涉及位置**：

- `web/app/task/[id]/page.tsx`
- `worker/db.py`
- `worker/main.py`
- Supabase migration / RPC

**验收标准**：

- [ ] 任意上游重跑后，下游不会读取旧产物。
- [ ] 重复点击不会创建多个并行处理实例。
- [ ] Worker 重启后可以继续处理或明确恢复失败任务。
- [ ] 错误信息足以指导用户下一步操作。

### B13：全链真实验收

**目标**：用真实创作结果判断系统是否达到稳定发布基线。

**样本要求**：

- 1 条普通话清晰、1 分钟以内视频。
- 1 条语速快、口语词较多的视频。
- 1 条包含书名、作者和专有名词的视频。
- 1 条健康或敏感表达较多的视频。
- 1 条自动采集失败、转手动上传的视频。

**每条记录**：

- 总耗时和各阶段耗时。
- 模型、生图和存储成本。
- 自动重试和人工介入次数。
- ASR 错词和书籍事实错误。
- 改写可用度、画面相关性、字幕同步、配音自然度。
- 最终结论：可直接发布 / 修改后发布 / 不可发布。

**验收门槛**：

- [ ] 5 条中至少 4 条完成完整流程。
- [ ] 至少 3 条达到可发布标准。
- [ ] 无 P0 数据错乱、任务卡死或错误成片。
- [ ] P1 视觉问题有明确后续计划，不阻断日常使用。
- [ ] 形成首份真实验收报告。
